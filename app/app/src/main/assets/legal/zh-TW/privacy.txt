1. 術語定義與個人資訊分類界定
1.1 【個人資訊之定義】
依據《中華人民共和國個人資訊保護法》第四條之規定，個人資訊是以電子或者其他方式記錄的與已識別或者可識別的自然人有關的各種資訊，不包括匿名化處理後的資訊。
【涉及資料範疇界定】：
在本軟體的技術執行語境下，可能涉及的個人資訊範疇包括但不限於：
  ▶ 遊戲角色暱稱與數字 UID（若在除錯截圖或異常排障日誌中顯現）；
  ▶ 裝置底層硬體特徵識別符號（在排障診斷日誌中顯現）；
  ▶ 無線除錯（ADB）連線金鑰與本地控制口令；
  ▶ 包含在自動化截圖快取中的部分可能關聯到個人身份的文字或視覺畫面資訊。
1.2 【敏感個人資訊之定義——核心敏感憑證防護】
依據《中華人民共和國個人資訊保護法》第二十八條之規定，敏感個人資訊是一旦洩露或者非法使用，容易導致自然人的人格尊嚴受到侵害或者人身、財產安全受到危害的個人資訊，包括生物識別、宗教信仰、特定身份、醫療健康、金融賬戶、行蹤軌跡等資訊，以及不滿十四周歲未成年人的個人資訊。
【核心敏感憑據防護範疇】：
在本軟體中，以下資料依法被納入敏感個人資訊的最高等級防護範疇，實施物理隔離與嚴密保護：
  ▶ 裝置鎖屏指紋 / 面容認證互動結果（僅單向接收系統布林值，絕不接觸生物原始資料）；
  ▶ 無線除錯（Wireless Debugging）RSA 配對私鑰（adbkey）與配對鑑權 Token；
  ▶ 區域網及遠端控制訪問密碼、身份校驗 Token。
1.3 【去標識化與匿名化】
去標識化是指個人資訊經過處理，使其在不借助額外資訊的情況下無法識別特定自然人的過程；匿名化是指個人資訊經過處理無法識別特定自然人且不能復原的過程。
【處理原則與技術措施】：
  ▶ 本軟體在生成錯誤診斷日誌及資料匯出包時，竭力貫徹去標識化設計，力求抹除直接可讀的個人敏感屬性；
  ▶ 對可能出現的敏感識別符號實施脫敏掩碼，杜絕未經授權的逆向關聯分析。
1.4 【本地私有目錄與應用沙箱】
指 Android 作業系統基於 Linux 檔案系統許可權模型，為本軟體專屬分配的獨立儲存空間（通常物理路徑為 /data/user/0/com.azurpilot.ghio/）。
【沙箱安全邊界】：
  ▶ 該目錄受作業系統核心級 SELinux 強制訪問控制策略與 UID/GID 許可權隔離保護；
  ▶ 在預設非 Root 環境下，裝置上安裝的其他任何普通第三方應用均被物理阻絕在外部，絕對無法跨目錄讀取本軟體私有目錄中的任何檔案。
1.5 【嵌入式 PRoot 容器環境資料】
指解壓並駐留於本軟體私有儲存目錄中的輕量級 Ubuntu Linux 根檔案系統（Rootfs）。
【容器環境資產構成】：
  ▶ 該容器環境包含獨立的 /etc、/usr、/var 目錄體系、Python 3 執行庫及上游 AzurPilot 自動化程式碼庫；
  ▶ 容器內的全部資料與檔案，在宿主作業系統視角下均完整歸屬於本應用的私有內部資料，完全受到應用沙箱保護。
1.6 【執行診斷日誌與系統堆疊資料】
指本軟體在執行過程中由 Timber 日誌框架以及 Python 內建 logging 模組向裝置物理快閃記憶體中寫入的文字流水記錄。
【診斷日誌包含資訊】：
  ▶ 系統初始化時序、元件啟動狀態、JNI 底層呼叫耗時；
  ▶ 影象模板匹配得分、任務狀態機躍遷步驟；
  ▶ 在發生未捕獲異常時的完整崩潰堆疊跟蹤（Crash Stacktrace），用於故障定位與排查。

2. 我們如何收集與使用您的資訊
2.1 【本地系統偏好與基礎應用設定】
為了記憶您的個性化使用習慣、保障介面的連續性體驗，本軟體會在裝置本地私有目錄中透過 Jetpack DataStore 持久化儲存一系列輕量級配置引數。該等資料包括：
  ▶ （1）介面外觀與互動偏好：
      a. 深色模式 / 淺色模式選擇與跟隨系統主題開關；
      b. Miuix / Material 3 Expressive 介面設計語言風格切換；
      c. 動態取色與桌布配色偏好；
      d. 高重新整理率渲染開關、動畫特效啟閉。
  ▶ （2）多語言與本地化配置：
      a. 記錄您在首次配置嚮導中選定或在設定中切換的語言程式碼；
      b. 涵蓋 zh-CN 簡體中文、zh-TW 繁體中文、en 英語、ja 日語。
  ▶ （3）嚮導流程確認與法律狀態記錄：
      a. 儲存您是否已完整透過首次啟動向導（isSetupCompleted）；
      b. 已確認簽署的法律文件與免責宣告版本號（legalNoticeVersion）。
  ▶ （4）執行模式與特權策略偏好：
      a. 記錄所選執行後端模式（純投屏無障礙、Shizuku 獨立虛擬屏、Root 超級使用者）；
      b. 虛擬顯示屏的解析度與重新整理率設定值。
上述所有偏好資料均以鍵值對（Key-Value）形式安全儲存在本地 XML/二進位制檔案中，僅用於宿主介面的正常渲染與邏輯分發，絕對不向任何外部網路節點同步。
2.2 【裝置硬體與系統診斷資料】
為了在碎片化嚴重的 Android 裝置生態中評估硬體相容性、適配特定廠商定製 ROM 的特殊機制、並輔助使用者進行執行時故障排除，本軟體會在裝置本地讀取部分裝置軟硬體基礎特徵，並在發生異常時輸出至本地診斷日誌中。該等資訊包括：
  ▶ （1）裝置基本物理型號：
      a. 裝置製造商名稱（Build.MANUFACTURER，如 Xiaomi、HUAWEI、OPPO、vivo、Samsung 等）；
      b. 裝置商業品牌（Build.BRAND）；
      c. 產品型號程式碼（Build.MODEL）。
  ▶ （2）作業系統與底層核心版本：
      a. Android 作業系統版本號（Build.VERSION.RELEASE，如 Android 13、14、15）；
      b. 系統 API 級別（Build.VERSION.SDK_INT）；
      c. 底層 Linux 核心版本號；
      d. 系統安全補丁程式日期（Build.VERSION.SECURITY_PATCH）。
  ▶ （3）CPU 處理器架構與硬體特徵：
      a. 裝置支援的 ABI 架構列表（Build.SUPPORTED_ABIS，如 arm64-v8a、x86_64）；
      b. CPU 核心數量、執行頻率及大小核拓撲結構。
  ▶ （4）顯示與視窗度量引數：
      a. 物理螢幕寬度與高度畫素值；
      b. 邏輯畫素密度（DPI / Density）；
      c. 螢幕重新整理率（Hz）；
      d. 系統安全區域內邊距（DisplayCutout / Insets）及導航欄高度。
  ▶ （5）記憶體與電池實時狀態：
      a. 系統總實體記憶體（Total RAM）與當前可用記憶體水線；
      b. 電池當前電量百分比、健康度狀態、充電狀態與機身電池溫度。
維護團隊莊嚴保證：讀取上述裝置資訊純粹係為本地技術相容性判定（例如動態決定採用何種 ABI 版本的 PRoot 動態庫、是否需要針對特定 ROM 開啟防凍結看門狗、是否需要壓暗螢幕亮度），本軟體絕不利用上述資料拼接生成任何用於裝置追蹤的“裝置唯一指紋”，亦絕不將上述資料上傳至任何分析平臺。
2.3 【自動化任務排程與業務執行配置】
使用者在 WebUI 互動介面或透過編輯本地 YAML/JSON 配置檔案所設定的全部遊戲自動化策略，均完整儲存在應用私有儲存目錄的 config/ 資料夾中。此類業務資料包括：
  ▶ （1）出擊與作戰排程策略：
      a. 選擇出擊的主線章節、困難關卡、限時活動地圖代號；
      b. 艦隊出戰編號指定與自律戰鬥模式設定；
      c. 陣型策略與彈藥耗盡撤退閾值設定。
  ▶ （2）演習與競技場配置：
      a. 演習對手重新整理策略；
      b. 對手最低/最高戰力篩選區間；
      c. 演習進攻艦隊指定。
  ▶ （3）日常事務與資源流轉策略：
      a. 後宅存糧補充優先順序；
      b. 戰術學院教材使用顏色與品階偏好；
      c. 軍事委託自動派遣篩選規則；
      d. 軍部科研專案期數與藍圖研發優先順序佇列。
  ▶ （4）高風險安全閾值防線：
      a. 是否允許消耗石油接受緊急委託；
      b. 是否允許消耗心智魔方執行科研；
      c. 物資保留底線閾值；
      d. 最大連續戰鬥次數上限、自動退役船塢過濾白名單與鎖定規則。
此類配置資料直接對映了使用者的遊戲資產運作方案，本軟體嚴格將其作為高度敏感的本地私有配置檔案對待，絕不對外分享或洩漏。
2.4 【螢幕影象捕獲與臨時影象快取處理】
為了實現自動化操作所必需的視覺感知能力，本軟體在得到使用者明確授權的前提下，透過底層圖形管線（MediaProjection 或 VirtualDisplay）連續捕獲裝置螢幕的實時畫面。在影象資料的全生命週期流轉中，本軟體貫徹如下極度嚴格的隱私保護機制：
  ▶ （1）記憶體即時流轉與零落地：螢幕採集模組將截圖畫素陣列以點陣圖形式直接載入 RAM 共享記憶體中，供 OpenCV 模板匹配引擎進行畫素比對。在絕大多數正常執行場景下，這些影象幀資料在完成比對判定後立即在記憶體中被下一幀覆蓋釋放，絕不寫入物理儲存介質（ROM/Flash）；
  ▶ （2）受限排障截圖落盤機制：當且僅當發生嚴重識別死鎖、連續數次超時未匹配到目標錨點、或使用者在設定中主動開啟了“儲存錯誤排障截圖”選項時，系統才會將發生錯誤當下的瞬時畫面以 PNG/JPG 格式短暫寫入私有儲存的 debug/ 臨時目錄中，用於輔助使用者排查為什麼特定介面未能被正確識別；
  ▶ （3）排障截圖之敏感內容預警：
      a. 遊戲畫面截圖中不可避免地會包含展示在遊戲 UI 上的遊戲角色暱稱、玩家個性簽名、大艦隊公會名稱、聊天氣泡內容、甚至在遊戲頂欄展示的虛擬財產餘額。本軟體鄭重承諾絕不對該等截圖進行任何形式的雲端自動同步；
      b. 使用者在後續使用日誌匯出功能時，有絕對責任自行檢查並刪除該等圖片。
2.5 【OCR 文字識別與記憶體即時擦除機制】
本軟體內建的 LiteRT OCR 神經網路推理模組用於識別關卡名稱、數字金額、剩餘油量及角色姓名。OCR 推理完全在移動裝置的 CPU / NPU 硬體加速器本地運算，其輸入的影象切片及輸出的 Unicode 文字字元在完成狀態機條件判定後，變數立即在記憶體中被回收，不構建任何長久儲存的歷史文字資料庫。
2.6 【無線除錯（ADB）配對金鑰與憑證——核心敏感憑證防護】
在免 Root 且未安裝 Shizuku 的特定裝置上，為了透過 Android 11+ 內建的“無線除錯”（Wireless Debugging）通道啟動底層守護程序，本軟體需要生成並儲存一套專屬的 RSA-2048 非對稱加密金鑰對（adbkey 與 adbkey.pub），並在配對過程中儲存配對埠與鑑權 Token。
  ▶ （1）金鑰存放安全級別：該 RSA 金鑰對安全生成並存放在應用的私有加密偏好目錄中，其許可權受到 Linux 系統檔案級別嚴格保護；
  ▶ （2）系統雲備份顯式物理排除（核心安全防線）：為了防止該高敏感的 ADB 除錯控制金鑰隨手機廠商的系統雲備份或整機換機遷移被克隆洩露至第三方雲端，本軟體在工程清單（AndroidManifest.xml 及 backup_rules.xml / data_extraction_rules.xml）中將其列為絕對排除項，確保該金鑰物理孤立在當前單一裝置內部。
2.7 【本地 WebUI 訪問控制密碼與訪問令牌——敏感憑證防護】
為了向使用者提供基於網頁的直觀管理控制檯，本軟體內建了輕量級 Web 伺服器。為了防止裝置上安裝的其他惡意應用透過迴環網路（127.0.0.1）擅自發起非法控制請求，本軟體在首次初始化時會自動生成高熵值的隨機身份認證令牌（Token）或由使用者親自設定控制密碼。該憑據安全持久化於私有配置中，每次 HTTP / WebSocket API 請求均須強制核驗該憑據，以此構築本地程序間通訊的安全防火牆。
2.8 【區域網通訊與遠端穿透訪問資料】
當使用者在設定中主動開啟“區域網控制”或“遠端訪問”高階網路擴充套件功能時：
  ▶ （1）區域網通訊流轉：本軟體的 WebUI 監聽埠向當前區域網開放，傳輸的內容包含控制檯 HTML/JS 靜態資產、控制指令 JSON 報文、以及實時的螢幕預覽 JPEG 影象流。所有資料僅在您區域網內部的控制端與被控端裝置之間進行對等傳輸；
  ▶ （2）遠端穿透隧道資料：透過基於 SSH 反向隧道或點對點 P2P 穿透技術，資料流經外部中繼跳板。在此類場景下，網路中轉節點僅作為無狀態的資料包路由轉發管道，傳輸通道採用標準 TLS / SSH 加密協議封裝，維護團隊不設立任何用於解密、窺探、竊聽或記錄使用者控制流量內容的中心監控節點。
2.9 【崩潰日誌、異常堆疊與診斷資訊】
當應用程式發生意外崩潰、ART 虛擬機器丟擲未捕獲異常、或底層 JNI 連結庫觸發 SIGSEGV 段錯誤訊號時，Android 系統的崩潰捕獲機制及 Timber 日誌記錄器會將當下的執行緒呼叫棧（Call Stack）、發生異常的程式碼行號、錯誤描述寫入本地 crash_log.txt 檔案中。該檔案完全停留在使用者本地磁碟中，本軟體絕對不部署任何後臺自動向維護團隊靜默上傳崩潰日誌的隱蔽上報服務。全部日誌的向外提供，必須依賴使用者本人的百分之百主動手動操作。

3. 裝置系統許可權的呼叫規範與使用者動態控制機制
3.1 【系統許可權申請的最小化與必要性原則】
依據《中華人民共和國個人資訊保護法》第五條所確立的“處理個人資訊應當具有明確、合理的目的，並應當與處理目的直接相關，採取對個人權益影響最小的方式”之法律準則，本軟體在許可權架構設計上秉持極其嚴苛的剋制態度。我們絕不申請任何超出自動化執行技術所絕對必需的許可權。對於通話記錄、聯絡人、簡訊、GPS 位置、相機、麥克風等高度敏感且與業務無關的許可權，本軟體在程式碼清單（AndroidManifest.xml）中實施了物理排除，自始至終絕不申請。
3.2 【螢幕錄製與投屏許可權（MediaProjection）——重點核心許可權】
  ▶ （1）許可權申請之業務必要性：當使用者選擇免 Root 的標準投屏模式執行本軟體時，本軟體必須藉助 Android 系統的 MediaProjection 框架建立螢幕映象虛擬顯示層，以便本地計算機視覺演算法能夠逐幀讀取當前螢幕上的畫素矩陣，識別遊戲主介面、關卡按鈕及戰鬥結算圖示；
  ▶ （2）許可權呼叫的時機與使用者顯式互動：該許可權無法在應用安裝時靜默獲取。每次使用者點選啟動自動化任務時，系統會彈出全域性系統級安全確認對話方塊（“AzurPilot 將開始擷取您的螢幕上顯示的所有內容”）。使用者必須親自在系統彈窗中點選“立即開始”或勾選“本次允許”，本軟體方可合法接收系統的 VirtualDisplay 控制代碼；
  ▶ （3）許可權使用邊界與安全承諾：維護團隊鄭重宣告：該許可權僅在自動化任務處於“執行中”狀態時被啟用，且捕獲的螢幕資料流僅用於本地記憶體中的模式匹配計算與臨時排障快取，本軟體絕對不將錄屏流進行後臺錄影、絕不進行任何雲端直播推流、亦絕對不將螢幕畫素髮送至任何商業伺服器；
  ▶ （4）許可權撤回途徑：
      a. 使用者可隨時透過點選本軟體通知欄上的“停止”按鈕、按下懸浮窗停止鍵終止錄屏；
      b. 亦可在 Android 系統“設定 - 應用管理 - 特殊應用許可權 - 投屏/錄屏”中徹底撤銷該項授權。
3.3 【系統無障礙服務許可權（AccessibilityService）——重點核心許可權】
  ▶ （1）許可權申請之業務必要性：在非 Root、非 Shizuku 環境下，為了實現自動模擬點選、滑動及手勢操作，本軟體需要依賴 Android 作業系統提供的無障礙服務（com.azurpilot.ghio.service.AppAccessibilityService）。無障礙服務提供了系統級的手勢分發介面（dispatchGesture），允許應用向視窗管理器安全地注入虛擬觸控手勢；
  ▶ （2）安全邊界與防窺私承諾：
      a. Android 無障礙服務通常具備極高的監聽能力。維護團隊在此向所有使用者做出最為鄭重的合規保證：本軟體的無障礙服務實現程式碼嚴格保持技術純潔性，絕不註冊任何監聽視窗內容變化、監聽按鍵事件（OnKeyEvent）、讀取螢幕 UI 節點樹文字（AccessibilityNodeInfo）的回撥邏輯；
      b. 本軟體絕不利用無障礙服務窺探使用者在任何第三方應用（如社交軟體、電子郵箱、銀行網銀、備忘錄）中輸入的任何文字資訊、絕對不竊聽密碼鍵盤。
  ▶ （3）許可權撤回途徑：使用者可隨時進入 Android 系統的“設定 - 輔助功能 / 無障礙 - 已安裝的應用 - AzurPilot”，手動將無障礙開關切換為關閉狀態。關閉後，本軟體將立即失去手勢注入能力並安全終止執行。
3.4 【顯示在其他應用上層許可權（SYSTEM_ALERT_WINDOW）】
  ▶ （1）業務必要性：為了向使用者提供便捷的一鍵啟停控制入口、實時展示當前自動化任務的執行狀態（如當前執行輪次、剩餘石油量、當前關卡名稱），並在遊戲畫面卡死時向使用者呈現緊急停止控制柄，本軟體需要申請系統懸浮窗許可權；
  ▶ （2）許可權呼叫的獨立性：使用者享有完全自主的選擇權，若使用者不希望在螢幕上看到常駐懸浮控制球，可以在應用設定中將其關閉，或者在系統設定中撤銷懸浮窗許可權。撤銷該許可權僅導致懸浮卡片無法展示，不影響底層自動化任務透過通知欄進行的後臺靜默執行。
3.5 【常駐前臺服務許可權（FOREGROUND_SERVICE）】
  ▶ （1）業務必要性：依據 Android 9.0（API 28）至 Android 15（API 35）的後臺執行合規規範，任何需要在後臺持續執行而不被系統省電策略瞬間凍結掛起的服務，必須顯式宣告前臺服務並在系統通知欄持久展示具有高優先順序的常駐通知（Ongoing Notification）；
  ▶ （2）通知欄資訊展示內容：本軟體的前臺服務通知清晰明瞭地展示了當前應用的執行狀態（如“AzurPilot 正在後臺執行”、“當前任務：主線出擊”），並內建了“暫停”、“停止”等即時操作動作，確保使用者對後臺程序的存在保持時刻清醒的知情權與絕對控制力；
  ▶ （3）許可權型別細分合規：本軟體嚴格依照 Google 最新平臺規範，根據具體場景細分宣告瞭 FOREGROUND_SERVICE_MEDIA_PROJECTION（用於投屏服務）、FOREGROUND_SERVICE_SPECIAL_USE（用於容器宿主維持）等特定型別，絕不濫用模糊服務型別規避系統審查。
3.6 【特權提權服務（Shizuku / Root / app_process）——高階系統特權】
  ▶ （1）高階架構與特權申請原理：當使用者追求極致的執行體驗（如在前臺使用手機的同時讓遊戲在完全隔離的第二虛擬螢幕後臺靜默執行）時，本軟體支援與 Shizuku 框架或系統超級使用者（Root su 管道）進行 IPC 繫結，進而呼叫 Android 系統的 app_process 命令列工具啟動具有系統級許可權的遠端特權守護程序（RemoteServiceManager）；
  ▶ （2）特權服務安全邊界與程式碼開源受控：使用者知悉向本軟體授予 Root 許可權或在 Shizuku 授權管理器中批准本軟體訪問，意味著賦予了特權守護程序呼叫系統底層隱藏 API 的能力。維護團隊在此承諾：該特權程序的所有原始碼均在官方倉庫完全公開，其功能嚴格且唯一地侷限於：透過 DisplayManager 建立獨立虛擬顯示屏、透過 WindowManager 在該虛擬屏上啟動目標遊戲 Activity、透過 InputManager 向該虛擬屏直接派發輸入事件。特權程序絕不利用系統超級許可權篡改系統分割槽（/system）、絕不篡改系統只讀屬性、亦絕不讀取其他應用的隱私資料庫；
  ▶ （3）特權授權之隨時吊銷：使用者可隨時在 Shizuku 客戶端中撤銷對 AzurPilot 的授權，或者在 Magisk / KernelSU / APatch 等 Root 管理器中一鍵關閉對本軟體的超級使用者授權。
3.7 【生物識別與安全鎖認證介面（USE_BIOMETRIC）】
  ▶ （1）業務必要性：為了協助使用者保護存放在本地的敏感配置、防止家人、同事或他人在無意接觸使用者手機時擅自調起本軟體或篡改任務引數，本軟體提供了可選的“應用安全鎖”功能；
  ▶ （2）生物資料絕對隔離機制：本軟體嚴格依照 Google 官方推薦的 androidx.biometric:biometric 安全架構標準，僅呼叫 Android 作業系統底層的 BiometricPrompt 統一認證系統對話方塊。生物識別的指紋比對、面容深度點陣掃描完全在裝置底層的硬體安全隔離區（TEE / 獨立安全晶片 Titan M）內完成。本軟體僅單向接收系統底層返回的“認證成功（AuthenticationSucceeded）”或“認證失敗”的布林值憑證訊號。本軟體在物理上絕對沒有任何可能、亦絕對不包含任何程式碼嘗試讀取、解析、快取或上傳使用者的生物原始特徵資料（如指紋影象、人臉特徵點雲）；
  ▶ （3）密碼安全邊界：若使用者選擇使用鎖屏數字密碼或圖案密碼進行應用鎖解鎖，密碼校驗由 Android 作業系統金鑰保護系統全權執行，本軟體絕不截獲亦不儲存使用者的鎖屏數字密碼。
3.8 【網路通訊許可權（INTERNET 及網路狀態查詢）】
  ▶ （1）業務必要性：本軟體申請 android.permission.INTERNET、android.permission.ACCESS_NETWORK_STATE、android.permission.ACCESS_WIFI_STATE 許可權，其技術用途嚴格限定於：從官方公開的開源映象站下載/更新 Ubuntu PRoot 執行環境歸檔包、在區域網開啟控制檯監聽、建立遠端 SSH/P2P 控制隧道、以及查詢當前網路是否處於 Wi-Fi 環境以提示使用者避免在移動蜂窩網路下消耗流量；
  ▶ （2）嚴禁濫用承諾：本軟體絕不利用網路通訊許可權將使用者的本地截圖、本地配置檔案或個人資料偷偷傳輸給任何未知的第三方伺服器。
3.9 【許可權隨時撤回與功能降級救濟】
使用者對自身裝置的所有許可權享有最高、不可動搖的決定權。您有權在任何時間進入作業系統應用詳情頁面，逐項關閉已向本軟體授予的任何一項許可權。維護團隊在此向您明確告知許可權關閉後的系統技術反應：關閉某項關鍵依賴許可權將直接導致對應功能無法運轉（例如撤銷投屏許可權將導致影象識別立即中止，撤銷無障礙許可權將導致點選無法下發），但本軟體絕不會因此阻撓您使用其他不需要該許可權的獨立功能模組（如離線文件瀏覽、歷史配置檢視），亦絕不會採取強制閃退、反覆彈窗騷擾等對抗性手段強迫您重新授權。

4. 資訊的儲存地點、技術保護措施與生命週期管理
4.1 【儲存地點：裝置本地私有沙箱目錄】
依照《中華人民共和國個人資訊保護法》第四十條關於個人資訊本地化與資料駐留的法理精神，本軟體在資料生命週期管理中貫徹最為徹底的“本地化駐留”原則：所有因安裝、配置、執行本軟體產生的一切使用者偏好、配置、執行日誌、臨時影象、執行環境映象與金鑰憑據，均 100% 儲存在裝置內部私有儲存空間中（/data/user/0/com.azurpilot.ghio/）。本軟體不構建任何外部中心化資料中心，絕不存在任何後臺靜默上傳邏輯。
4.2 【Android 系統底層沙箱隔離與訪問控制】
本軟體充分依託並深度整合 Android 移動作業系統的多層防禦安全架構：
  ▶ （1）Linux UID/GID 程序隔離：Android 系統在安裝本軟體時，為其分配了全系統唯一的 Linux 使用者識別符號（UID）。在作業系統核心級別，檔案系統透過標準的 POSIX 許可權位（如 0700 / 0600）將應用私有目錄的讀寫許可權嚴格限制在該專屬 UID 對應的程序之內，裝置上安裝的其他普通應用程式在核心級別被剝奪了訪問該目錄的許可權；
  ▶ （2）SELinux 強制訪問控制策略：即便在特定多使用者環境或許可權提升場景下，作業系統底層的 SELinux 策略規則嚴格規定了 untrusted_app 域對檔案系統標籤（Context）的訪問規則，防止跨沙箱非法遍歷；
  ▶ （3）敏感憑據記憶體加密與即時擦除：在處理敏感密碼、認證 Token 與解密金鑰時，本軟體優先採用可安全擦除的字元陣列（char[] / byte[]）而非不可變的字串（java.lang.String）進行記憶體持有，在憑證驗證透過後第一時間使用零值覆寫記憶體區域，降低透過讀取記憶體映象（Memory Dump）竊取敏感憑證的技術風險。
4.3 【敏感配對金鑰排除系統雲備份機制——核心安全防線】
  ▶ （1）系統雲備份之洩露隱患：
      a. 當前主流智慧手機作業系統（如 Google 原生 Android、小米 MIUI/HyperOS、華為 EMUI、OPPO ColorOS 等）普遍內建了便捷的“整機雲備份”與“一鍵換機助手”功能。當使用者開啟雲備份後，系統預設會將應用私有目錄中的共享首選項（SharedPreferences）及資料庫無感知同步上傳至手機廠商的公有云端伺服器。對於普通配置項，這種備份有助於提升換機體驗；
      b. 但對於無線除錯（ADB）配對金鑰、本地鑑權 Token 等敏感安全憑證，一旦隨備份同步至廠商雲端，極易因雲端賬號被盜或換機過程中的跨裝置傳輸造成憑證實質性失竊與外洩。
  ▶ （2）嚴格的雲備份隔離規則部署：為了徹底根絕上述安全隱患，本軟體依據 Android 官方安全規範，在工程清單中部署了高等級的安全備份規則配置檔案（res/xml/backup_rules.xml 以及適配 Android 12+ 的 res/xml/data_extraction_rules.xml）。我們在規則中進行了明確的排除指令配置：顯式排除了所有存放 ADB 配對私鑰、配對埠歷史、控制密碼及身份 Token 的檔案路徑，強制禁止作業系統底層將此類高敏感憑據納入雲端備份或裝置間克隆傳輸流程。使用者在更換新手機後，此類憑據必須在新裝置上重新安全生成，以此保障舊憑證絕不在網路雲端產生任何洩露痕跡。
4.4 【零高頻 Flash 寫入與記憶體資料保護】
移動終端的物理快閃記憶體晶片（UFS/eMMC）屬於耐受性受限的物理儲存介質。如果應用程式高頻地向磁碟落盤寫入大量瞬時資料，不僅會嚴重縮短手機主機板的使用壽命，更會在磁碟未分配簇空間中留下難以徹底擦除的資料碎片殘影。本軟體在系統架構層面嚴格執行“零高頻 Flash 寫入”設計原則：
  ▶ （1）所有由螢幕捕獲管線輸出的實時高幀率影象資料流，全部嚴格限制在 RAM 實體記憶體對映環形緩衝區中流轉，在完成 OpenCV 特徵比對後直接在記憶體中執行析構釋放，絕不經歷“截圖 - 存入磁碟檔案 - 再從磁碟讀取 - 判定後刪除”的陳舊落盤流轉模式；
  ▶ （2）Native JNI 橋接層與 PRoot 容器之間透過 Linux 匿名共享記憶體（ashmem / memfd_create）及本地迴環套接字進行高速記憶體級資料交換，從根本上兼顧了極致的執行效率與物理資料防殘留安全。
4.5 【執行日誌的自動輪換與儲存期限控制】
為了平衡故障排查的必要性與本地磁碟空間的有限性，本軟體內建了嚴密的自動化日誌輪換管理系統（Log Rotation Policy）：
  ▶ （1）大小與檔案數量上限閾值：單個日誌檔案被設定了嚴格的大小上限（通常單個文字日誌檔案達到 5MB 時立即觸發分卷滾動）。系統保留的歷史輪換日誌檔案數量被嚴格限制在極小閾值之內（預設最多保留最近 3 至 5 卷歷史分卷）；
  ▶ （2）先進先出與自動覆蓋淘汰：當新日誌產生導致日誌總容量超出預設限額時，底層的日誌維護演算法會自動以先進先出（FIFO）原則，物理刪除最為陳舊的歷史日誌檔案，確保磁碟空間佔用始終被錨定在可控的安全區間之內；
  ▶ （3）儲存期限說明：
      a. 在使用者正常保留安裝本軟體的情況下，本地偏好配置保持持久儲存，直至使用者主動修改或解除安裝應用；
      b. 執行日誌受前述輪換機制控制，在正常使用強度下歷史記錄的留存生命週期通常不超過 7 至 14 個自然日，隨時間推移被新日誌安全覆寫。
4.6 【臨時影象與快取的即時銷燬機制】
在自動化任務執行期間，因特定異常排障需要而短暫寫入本地儲存的錯誤現場截圖（儲存於 debug/ 臨時目錄），受生命週期清理守護邏輯管控：
  ▶ （1）任務退出自動清空：當使用者點選停止任務、或任務正常執行完畢退出時，清理邏輯會自動清空該臨時目錄中的影象快取；
  ▶ （2）異常殘留的手動釋放：若因系統突然斷電關機導致臨時目錄中遺留了部分孤兒圖片，使用者可在軟體介面的“儲存與維護”面板中點選“立即清空臨時快取”，一鍵物理擦除該目錄下的全部影象檔案。
4.7 【一鍵清除資料與本地儲存徹底銷燬】
使用者享有隨時徹底銷燬本軟體在裝置上留存的一切資料痕跡的絕對控制權：
  ▶ （1）應用內出廠重置：本軟體設定面板中提供了“恢復出廠設定並清空全部資料”功能，執行後將同步登出本地全部偏好、刪除所有配置檔案、遞迴刪除解壓的 PRoot Ubuntu Linux 根檔案系統樹並登出嚮導狀態；
  ▶ （2）作業系統級強力資料擦除：使用者亦可隨時進入 Android 系統的“設定 - 應用管理 - AzurPilot - 儲存佔用”，點選“清除儲存空間 / 清除全部資料（Clear Data）”。該操作是由 Android 作業系統核心直接執行的原子級物理清理指令，系統將直接在底層檔案系統分配表中徹底抹去分配給本軟體私有包名目錄下的全部物理扇區資料，實現無法逆向恢復的徹底物理銷燬。當使用者在系統桌面長按圖示執行“解除安裝”操作時，作業系統同樣會自動且不可逆地全額抹去上述全部私有儲存資料。

7. 日誌匯出、社群反饋與個人隱私脫敏指引
7.1 【本地日誌打包工具（LogExportService）離線機制】
在移動端長期執行中，難免因系統環境變異、廠商核心定製或遊戲介面改版引發難以復現的技術疑難 Bug。為了便於使用者向開源社群提交診斷依據，本軟體內建了專門的“日誌與環境匯出服務（LogExportService）”。維護團隊鄭重宣告：該服務的工作原理是 100% 離線、本地化的檔案歸檔機制。當您點選“匯出日誌”按鈕時，系統僅在本地後臺執行緒中遍歷應用私有目錄下的 logs/、debug/ 目錄，將最近的文字日誌及必要的崩潰日誌打包壓縮為單個 ZIP 檔案，並儲存至您手機的本地儲存目錄（如 /sdcard/Download/）。在此全流程中，絕不包含任何靜默向外部伺服器上傳該壓縮包的隱藏網路行為。
7.2 【日誌中潛在敏感資訊清單（UID/暱稱/聊天截圖）】
儘管維護團隊在日誌記錄框架（Timber 及 Python logging）中儘量避免將個人隱私寫入日誌，但由於計算機視覺與自動化任務的複雜性，匯出的原始診斷日誌包中依然不可避免地可能潛伏著以下具有一定敏感性的個人資料碎片：
  ▶ （1）遊戲內身份識別符號：在關卡出擊、個人資訊介面或演習介面的異常截圖（PNG/JPG）中，極可能直接顯示了使用者在目標遊戲中的遊戲角色暱稱、數字 UID（賬號唯一識別碼）、大艦隊（公會）名稱、個性簽名、秘書艦誓約標識；
  ▶ （2）社交隱私內容碎片：若在遊戲執行過程中恰好有遊戲內好友私信、世界頻道滾屏發言、公會聊天氣泡彈出，異常截圖可能無意中捕獲了該等聊天文字畫面；
  ▶ （3）裝置軟硬體標識碎片：在診斷日誌的頭部，通常記錄了當前手機的型號（如 24129PN74C）、作業系統版本（Android 15）、核心架構、物理螢幕解析度以及授予本軟體的許可權清單；
  ▶ （4）本地檔案物理路徑：日誌中可能包含本應用私有儲存目錄的絕對檔案系統路徑，在某些特定多開分身系統下，該路徑可能包含系統分配的使用者編號（如 /data/user/999/...）。
7.3 【使用者向公開社群提交 Issue 前的強制脫敏義務】
GitHub Issues、Discussions、開源問答論壇以及公開技術群組，在網際網路法律屬性上均屬於“全網公開、任何人可自由閱覽、搜尋引擎可深度爬取索引的公共資訊空間”。維護團隊向每一位準備向社群求助的使用者發出最為嚴肅之法律與安全警示：
  ▶ （1）強制性的自檢與脫敏義務：在將匯出的日誌 ZIP 壓縮包上傳至 GitHub Issue、貼吧、社交群組前，您負有絕對、排他、不可推卸的第一責任，親自解壓並開啟其中的日誌文字與圖片，對所有潛在敏感內容實施強制性的“脫敏處理”；
  ▶ （2）文字脫敏操作規範：您應當使用文字編輯器開啟 log.txt，使用全域性查詢與替換功能，將日誌中出現的真實遊戲暱稱替換為虛擬代號（如 [REDACTED_NICKNAME]），將真實數字 UID 替換為任意隨機數字（如 12345678），將手機型號或具體路徑進行必要掩碼處理；
  ▶ （3）圖片脫敏操作規範：對於 debug/ 目錄中隨附的截圖圖片，您必須使用圖片編輯工具，對畫面中展示的暱稱、UID、聊天文字、充值餘額區域打上厚實的馬賽克或純色遮擋色塊，或者直接刪除與報錯無關的多餘截圖；
  ▶ （4）脫敏未履行之法律責任自負：若使用者因自身疏忽大意，未履行脫敏義務便將包含完整遊戲 UID、真實暱稱或私密聊天畫面的原始日誌包直接公開上傳至公共程式碼倉庫，導致該等資料被別有用心的第三方黑產人員、惡意玩家抓取利用，進而引發遊戲賬號被惡意舉報、人肉搜尋、隱私洩露或騷擾的，由此產生的一切精神損害、財產損失與名譽侵害，完全由該失密使用者自行全額承擔，維護團隊及社群貢獻者對此概不承擔任何責任。
7.4 【嚴禁公開張貼 Token、密碼與私鑰之特別警告——核心憑證紅線】
維護團隊在此設立絕對不可逾越的安全紅線：
  ▶ （1）嚴禁公開無線除錯配對私鑰：絕對嚴禁在任何公開場合公開張貼或上傳您的 adbkey 私鑰檔案，洩露該私鑰意味著任何處於同一網路環境下的攻擊者均可無需授權直接接管您的手機底層 ADB 除錯特權；
  ▶ （2）嚴禁公開 WebUI 認證 Token 與遠端訪問口令：絕對嚴禁將帶有鑑權引數的遠端訪問 URL（如形如 http://.../?token=abcdef... 的登入串）、SSH 穿透金鑰、或者 WebUI 的明文密碼張貼在公開 Issue 或公共群組中。一旦洩露此類憑證，外部惡意攻擊者便可直接透過網際網路遠端登入您的控制檯，惡意銷燬您的遊戲資產或篡改系統檔案；
  ▶ （3）失密應急處置：若您不慎在公開社群提交了包含上述高危憑證的日誌，您必須立即在 GitHub 上刪除該 Issue，並在手機端立即進入軟體設定，點選“重置並重新生成 WebUI Token”，同時在系統開發者選項中關閉並重新開啟無線除錯以使舊配對失效。
7.5 【公開社群公開資訊的防盜用與事後處置侷限】
使用者知悉：網際網路公開空間具有不可控的資料抓取特徵。GitHub 倉庫的公開資料會被全球各類搜尋引擎、公有程式碼克隆映象站、Wayback Machine 網際網路時光機、以及各類大模型訓練資料集進行自動化抓取與持久化快照存檔。即便使用者在事後刪除了其提交的 Issue 或關閉了工單，第三方爬蟲早已快取的靜態快照可能在未來數年內依然停留在外部映象站點中。維護團隊對全球第三方爬蟲映象站的行為不具備任何司法管轄權與技術干預力，無法保證徹底抹去已被第三方轉儲的公開資訊。

9. 安全事件應急響應與風險防範預案
9.1 【本地資料洩露與越權訪問風險評估】
依據《中華人民共和國資料安全法》以及現代資訊保安縱深防禦（Defense in Depth）理論模型，儘管本軟體自身在程式碼架構上執行了最徹底的本地沙箱隔離策略，但移動終端的整體安全性高度依賴於宿主裝置所處的物理與軟體綜合環境。維護團隊對可能誘發本地資料洩露或憑據失竊的高危外部威脅場景進行專業風險評估，提示使用者加強自我防護：
  ▶ （1）Root 越獄裝置上的全域性提權風險：在已被使用者主動刷機獲取 Root 最高超級使用者許可權的 Android 裝置上，作業系統的 Linux UID 沙箱隔離屏障已被實質性拆除。任何其他被使用者授予了 su 許可權的第三方流氓應用、惡意模組（如惡意 Magisk 模組、LSPosed 惡意外掛）均可直接憑藉 root 身份靜默讀取本軟體內部私有目錄下的全部 YAML 配置檔案、日誌、以及包含訪問口令的加密偏好資料庫，甚至能夠直接向 PRoot 容器內注入惡意二進位制木馬；
  ▶ （2）裝置物理遺失、被盜與非授權物理接觸：若使用者的移動智慧裝置在未設定強鎖屏密碼、或鎖屏密碼已被第三方獲知的情況下發生物理遺失、失竊，或者被他人未經許可物理操作，惡意接觸者可直接透過點選圖示進入本軟體，檢視使用者的遊戲自動化策略、或者透過 USB 資料線連線電腦執行 ADB 備份匯出未受保護的配置檔案；
  ▶ （3）區域網暴露與弱密碼爆破風險：當使用者在軟體設定中主動開啟了“區域網控制”或“遠端訪問”，且使用者設定了極度簡單的弱密碼（例如“123456”、“admin”）或將帶有 Token 的登入連結洩露至公網時，外部網路攻擊者可透過自動化指令碼進行高頻字典爆破，進而遠端接管控制檯；
  ▶ （4）第三方供應鏈與不可信外掛注入：若使用者未從官方 GitHub/CNB 渠道下載本軟體，而是輕信某些第三方非官方網站、破解論壇下載了所謂的“修改版”、“內購破姐版”、“免更新版”APK，該非官方安裝包極大機率已被駭客實施了反編譯重簽名、並二次打包植入了竊取隱私的鍵盤記錄木馬或惡意遠控後門。
9.2 【開源專案安全漏洞應急通報機制（Security Advisory）】
為了有效防範並應對潛在的軟體安全漏洞，維護團隊建立了規範的開源安全應急響應流程：
  ▶ （1）安全漏洞披露渠道：維護團隊在官方 GitHub 倉庫開通了符合國際標準的私有安全漏洞通報通道（GitHub Security Advisory / Private Vulnerability Reporting）。任何安全研究員、白帽子駭客或社群使用者若發現本軟體存在潛在的特權提升、路徑穿越、記憶體溢位或 Token 越權漏洞，可直接透過該私有通道向維護團隊提交詳細的漏洞復現 PoC，切勿在公開 Issue 中直接公佈零日漏洞（0-Day）；
  ▶ （2）漏洞評級與緊急修復（Hotfix）：維護團隊在收到安全漏洞預警後，將由核心安全人員在 72 小時內完成漏洞技術復現與危害定級（分為嚴重 Critical、高危 High、中危 Medium、低危 Low）。對於可能導致原生代碼執行或越權控制的嚴重與高危漏洞，維護團隊將立即啟動緊急熱修復流程，在隔離分支內完成程式碼修補與迴歸測試，並在最快時間內向全網推送新版本 APK 及修復補丁；
  ▶ （3）安全通告公開發布：在修復版本正式釋出上線的同時，維護團隊將在官方倉庫主頁、Releases 更新日誌中公開發布規範的 CVE 安全公告，詳盡披露漏洞的成因機理、影響版本範圍、以及建議使用者採取的安全升級操作，全面保障社群使用者的知情權。
9.3 【使用者端安全應急處置指南（改密/重置/銷燬）】
一旦使用者發現自身的移動裝置遺失、懷疑訪問密碼已遭洩露、或者發現本軟體出現非使用者本人意圖的異常自動化操作時，使用者應當立即按照如下應急預案採取自救措施：

  ▶ （2）立即重置 WebUI 認證 Token：在網路設定面板中，點選“強制重置訪問 Token”，系統將立即銷燬當前舊的所有安全鑑權 Session 與 Token，生成全新的不可預測的高熵隨機金鑰，迫使所有舊連線瞬間全部失效；
  ▶ （3）登出無線除錯（ADB）授權：進入 Android 系統的“設定 - 開發者選項 - 無線除錯”，點選“撤銷無線除錯授權”，並關閉無線除錯開關。該操作將強制使作業系統底層的 ADB 守護程序撤銷對本軟體 adbkey 的配對信任，從系統底層阻斷特權提權通道；
  ▶ （4）終極自毀：若裝置遭受不可逆的深度感染，使用者應直接在作業系統應用管理中執行“清除應用資料”並解除安裝本軟體，徹底銷燬本地一切潛在受汙染的檔案系統映象。

14. 跨平臺執行環境（PRoot Linux）內部檔案系統與系統呼叫攔截資料隱私規約
14.1 【PRoot 使用者空間虛擬化與檔案系統對映隱私邊界】
本軟體在 Android 移動端開創性地整合了基於 PRoot 技術的嵌入式輕量級 Ubuntu Linux 容器環境。為了使 Python 自動化引擎與 C/C++ 動態連結庫正常執行，PRoot 在使用者空間層透過 Linux ptrace 跟蹤機制對檔案系統路徑進行動態虛擬對映與重定向。維護團隊就虛擬檔案系統內部資料隱私機制披露如下：
  ▶ （1）虛擬根目錄的物理隔離：容器內的虛擬根目錄（/）在宿主 Android 系統中嚴格對應於應用私有資料目錄下的特定子目錄（/data/data/com.azurpilot.ghio/files/rootfs/）。容器內發生的所有檔案建立、編輯、編譯操作，在物理上均完全侷限在宿主分配的沙箱配額之內，絕對不具備突破該目錄向 Android 系統根目錄（/system、/vendor、/data/system）實施越權讀寫的能力；
  ▶ （2）宿主儲存受限掛載（Bind Mount）：為了實現匯入匯出配置與日誌共享，本軟體僅透過 PRoot 的 -b 繫結掛載引數，將宿主應用特定的私有資料目錄和經使用者明確授權的公共下載目錄掛載至容器內部。本軟體絕對不將包含使用者私人照片的 DCIM 相簿目錄、微信聊天儲存目錄、以及系統核心敏感目錄強行掛載至容器內部，從架構源頭杜絕容器環境對裝置全域性隱私檔案的遍歷可能。
14.2 【虛擬 /proc 與 /sys 節點的資訊脫敏與偽造機制】
在標準的 Linux 系統中，/proc 與 /sys 虛擬檔案系統直接暴露了底層硬體的真實裝置資訊、CPU 序列號、核心引數、物理網絡卡 MAC 地址、以及系統中所有執行中程序的完整命令列引數（cmdline）與環境變數（environ）。在 Android 系統中，若普通應用能夠隨意讀取上述節點，將嚴重危及其他後臺應用的執行隱私。為此，本軟體在 PRoot 執行時中部署了高度安全的虛擬節點偽造與脫敏機制：
  ▶ （1）裝置特徵偽造：容器內部讀取的 /proc/cpuinfo、/proc/version 節點，均經過了 PRoot 的本地靜態模擬或脫敏過濾，不讀取包含真實硬體序列號的底層物理暫存器；
  ▶ （2）程序列表絕對隔離：執行於 PRoot 容器內的程序（如 Python 直譯器、Bash 終端）在嘗試執行 ps 或讀取 /proc 時，僅能觀測到由 PRoot 派生的容器內部子程序，物理上絕對無法探知 Android 作業系統前臺執行的微信、網銀、遊戲等第三方宿主程序的存在，確保了不同應用間執行狀態的絕對隔離。
14.3 【無特權執行與使用者身份對映（UID 0 虛擬化）】
在 PRoot 容器內部，終端提示符通常顯示為 root（UID 0），這是為了滿足 Ubuntu 軟體包管理系統（如 apt、dpkg）在安裝編譯依賴時對特權身份的格式要求。維護團隊在此向使用者進行極其重要的電腦保安原理解析：
  ▶ （1）虛擬 Root 的本質是非特權執行：PRoot 內部顯示的 root 身份純屬基於 ptrace 的“假特權”（Fake Root）。該虛擬 root 身份的所有行為對映回 Android Linux 核心時，其實際有效使用者身份（EUID）始終且唯一地嚴格受限於宿主分配的普通非特權應用身份（如 u0_a1234）；
  ▶ （2）絕對無法危害系統底層：該虛擬 root 身份在物理上無法修改 Android 系統分割槽的任何檔案、無法關閉 SELinux 強制防護、無法讀取系統加密證書儲存區。因此，容器環境的執行絕對不會為惡意程式在裝置上實施系統級越權提供攻擊跳板。
14.4 【容器內臨時檔案與套接字的生命週期安全】
在自動化任務執行期間，容器內的 Python 程序會透過標準 Unix Domain Socket（UDS）與本地迴環套接字進行高速程序間通訊，並在容器的 /tmp 目錄生成臨時套接字控制代碼檔案。本軟體部署了嚴格的退出清理守護鉤子：在每次停止任務或宿主應用退出時，守護程式會自動執行 unlink 指令擦除 /tmp 目錄下的所有臨時檔案與 IPC 管道，防止殘留的套接字檔案被裝置上的其他惡意程序嗅探或複用。
14.5 【第三方 Linux 開源軟體包的供應鏈隱私審查】
本軟體所附帶的 Rootfs 映象檔案，其基礎元件均直接提取自 Ubuntu 官方 LTS 長期支援版釋出的標準基礎根檔案系統包（Ubuntu Base Rootfs），並在 CI 構建流水線中透過自動化 Docker 容器進行標準化編排。維護團隊嚴格把控軟體供應鏈安全：在製作映象的全流程中，絕不引入任何來源不明的未簽名第三方 PPA 軟體源，絕不編譯任何閉源黑盒二進位制元件，確保整個 Linux 執行環境的每一行程式碼均具備可溯源的開源合規性。
14.6 【容器網路協議棧的資料流轉隔離】
PRoot 容器不具備獨立的網路虛擬化名稱空間（Network Namespace），其網路呼叫完全藉由宿主 Android 系統的 Linux 網路堆疊下發。這意味著：
  ▶ （1）網路許可權完全繼承自宿主：容器內部的任何網路請求，均嚴格受限於 Android 系統向本宿主應用授予的 INTERNET 許可權狀態。若使用者在系統設定中切斷了本軟體的“行動網路與 Wi-Fi 訪問許可權”，容器內部的 Python 指令碼將瞬間失去一切聯網能力；
  ▶ （2）無私自網路外聯能力：容器環境絕對無法繞過系統的防火牆配置向任何未授權節點建立隱秘通訊通道。
14.7 【多使用者與分身環境下的沙箱一致性】
在部分支援“手機分身”、“應用雙開”、“工作資料夾（Work Profile）”的定製 Android 系統中，作業系統會為不同的分身環境分配不同的 Linux 使用者識別符號（如 UserId 10、UserId 999）。本軟體能夠完美適應多使用者隔離架構：在分身環境中執行的本軟體，其 PRoot 容器檔案系統完全建立在該分身專屬的獨立儲存沙箱中，與主使用者環境下的資料在檔案系統底層完全物理隔離，兩者的配置與日誌互不相通，徹底杜絕多賬號環境下的資料串聯與交叉汙染。
14.8 【執行時完整性自檢與防篡改機制】
為了防止惡意軟體在本地篡改 PRoot 容器內的關鍵 Python 自動化指令碼或植入釣魚頁面，本軟體在每次啟動前均會執行關鍵檔案的 SHA-256 雜湊完整性自檢。一旦檢測到核心自動化邏輯指令碼被外部非法篡改，本軟體將拒絕啟動並彈出安全警告，提示使用者執行重灌修復，以此捍衛使用者本地資料處理邏輯的真實性與純潔性。

15. 影象識別模板匹配與深度學習神經網路模型本地推理資料流全鏈路審查
15.1 【計算機視覺資料流在本地記憶體中的流轉拓撲】
本軟體的核心視覺感知系統依賴於高度最佳化的本地計算機視覺管線。為了消除關於“影象是否會被雲端後臺偷看”的疑慮，維護團隊將截圖影象資料從產生到銷燬的全生命週期記憶體流轉路徑進行全景式公開審查：
  ▶ （1）畫素採集源頭：透過 Android MediaProjection 介面建立虛擬 Surface，硬體圖形合成器將物理螢幕的渲染畫素複製至系統分配的 GraphicBuffer 實體記憶體頁；
  ▶ （2）零複製 Native 對映：Native 橋接層動態庫透過 libandroid.so 的 AImageReader_acquireLatestImage API 獲取最新的影象幀控制代碼，並透過直接記憶體對映指標（Direct Pointer）將 RGBA_8888 畫素矩陣直接接入 C++ 運算空間，全流程不產生額外的中間副本；
  ▶ （3）色彩空間轉換與矩陣切片：OpenCV 演算法庫呼叫 cv::cvtColor 將 RGBA 矩陣轉換為用於模板匹配的灰度圖（GRAY）或三通道 BGR 矩陣，並根據當前任務所關注的螢幕特定 ROI 感興趣區域（Region of Interest）執行矩形裁剪下片；
  ▶ （4）演算法比對與立即釋放：特徵匹配演算法在記憶體中完成互相關係數矩陣計算後，OpenCV 的 cv::Mat 智慧指標引用計數歸零，底層的影象畫素記憶體區域立即被析構釋放並標記為可重用，其存活週期通常僅維持數毫秒至十餘毫秒；
  ▶ （5）絕無外發管道：在上述全鏈路中，程式碼中絕對不包含任何將影象緩衝區透過 Socket、HTTP、FTP 等網路協議發往外網的邏輯，影象畫素矩陣的生與死完全被鎖死在單機 RAM 硬體晶片之中。
15.2 【LiteRT 神經網路輕量級模型推理隱私安全】
本軟體整合了由 Google 官方主導研發的 LiteRT（原 TensorFlow Lite）端側輕量級機器學習推理框架，用於執行光學字元識別（OCR）。維護團隊就該深度學習模型的執行特性說明如下：
  ▶ （1）模型檔案本地離線儲存：用於文字檢測與識別的神經網路權重模型檔案（.tflite 格式）以只讀資產形式隨本軟體安裝包一併離線打包分發（存放於 assets/ 目錄中）。本軟體在執行文字推理時，完全透過本地 CPU 或 GPU 硬體加速器載入該模型檔案，絕對無需向任何外部雲端 AI 介面（如各大雲廠商的公有云 OCR API）上傳任何影象切片；
  ▶ （2）輸入輸出特徵張量的即時記憶體覆寫：神經網路在執行推導時，輸入的影象張量（Tensor）以及輸出的字元機率分佈矩陣，在推理函式完成前向傳播（Forward Pass）並解碼為最終的 UTF-8 文字後，張量記憶體緩衝區立即被框架的分配器釋放，不保留任何可逆推原始畫面的歷史隱空間特徵向量；
  ▶ （3）模型無持續學習與反向傳播：本軟體內建的 LiteRT 模型屬於預先訓練固化的離線推理模型，在使用者端裝置上僅執行前向推導，絕對不執行任何本地反向傳播（Backpropagation）訓練，因此不存在將使用者的個人遊戲畫面反向固化融入神經網路權重並洩露的技術可能。
15.3 【螢幕水印、反截圖與敏感應用視窗規避】
在移動裝置日常使用中，使用者難免需要開啟涉及財產隱私的應用程式（如手機銀行、密碼保險箱、個人所得稅等）。維護團隊明確告知本軟體對系統敏感視窗的尊重機制：
  ▶ （1）FLAG_SECURE 硬體安全視窗規避：當使用者在前臺開啟宣告瞭 WindowManager.LayoutParams.FLAG_SECURE 標誌的高安全等級應用（如網銀密碼輸入介面、加密通訊軟體私聊介面）時，Android 作業系統底層的 SurfaceFlinger 合成器會在硬體級別對該視窗實施保護，本軟體透過 MediaProjection 捕獲到的該區域畫面將直接被系統強制替換為純黑畫素（Black Out），本軟體在底層物理上完全無法擷取到受保護視窗的任何真實畫素；
  ▶ （2）獨立虛擬螢幕的天然物理隔離：當使用者採用特權模式在第二虛擬螢幕上執行遊戲時，虛擬螢幕的渲染圖層堆疊與主物理螢幕完全屬於不同的視窗上下文。使用者在主螢幕上的微信聊天、照片瀏覽、網頁瀏覽等一切私人操作，在作業系統圖層層面與虛擬螢幕完全不發生任何重疊，虛擬屏的影象採集管線完全不可見使用者主螢幕的任何隱私畫面，構築起最為堅固的物理顯示隔離防線。
15.4 【異常死鎖截圖排障落盤的透明可審計性】
如前文所述，在發生介面死鎖或連續匹配超時等極端技術故障時，系統可能將故障發生瞬間的一幀畫面儲存至本地 debug/ 臨時目錄。為了保障該機制的絕對透明，維護團隊做出瞭如下合規保障設計：
  ▶ （1）儲存行為完全受使用者控制：使用者可在軟體設定中的“高階與除錯”面板中，自主找到“允許儲存錯誤截圖”的開關，使用者可隨時將其完全關閉。關閉後，系統即便遭遇連續死鎖報錯，亦絕對不在物理磁碟中儲存任何一幀圖片；
  ▶ （2）截圖儲存路徑完全公開：所有排障截圖均以公開透明的標準 PNG 格式儲存於裝置的應用內部私有路徑中，使用者隨時可透過內建的日誌管理面板逐張預覽、全選並立即一鍵徹底物理刪除；
  ▶ （3）絕不自動靜默上傳：儲存的截圖僅供使用者個人在本地肉眼核查排障，或在使用者深度脫敏後自主提交至社群求助。本軟體絕對不在後臺默默打包該等截圖向任何外部地址進行定時回傳。
15.5 【使用者自定義模板庫與影象特徵的安全存放】
部分高階使用者利用上游 AzurPilot 框架的高階自定義功能，透過 WebUI 自行裁剪並上傳了個性化的遊戲介面模板特徵圖（Custom Assets）。使用者知悉：所有由使用者自主上傳或匯入的圖片資源，均儲存在本地 PRoot 容器的對應 assets 目錄中。本軟體嚴格將其作為使用者的私有資產進行本地儲存保護，絕不在未經使用者授權的情況下將使用者的私人模板向公共倉庫進行回傳。
15.6 【螢幕畫素灰度化與特徵雜湊降維處理】
為了進一步壓縮記憶體佔用並提升處理安全性，影象引擎在許多場景下會對原始彩色畫素進行灰度化（Grayscale）與高斯模糊降維處理，僅提取邊緣輪廓（Canny Edge）與特徵雜湊（pHash）。這種資訊單向不可逆的降維數學變換，在客觀上使得臨時處理中的特徵資料進一步脫敏，最大程度降低了畫素流中附帶的人類可讀個人隱私資訊密度。
15.7 【第三方反作弊掃描與螢幕捕獲對抗免責】
使用者知悉：第三方遊戲客戶端自身所整合的安全防護 SDK 可能會在遊戲執行時，透過呼叫系統 API 檢索系統中是否存在處於活躍狀態的虛擬顯示屏或媒體投屏服務。本軟體對螢幕畫面的捕獲行為在作業系統層面屬於合法公開的 API 互動，若第三方遊戲運營商依據其自身的安全審計規則將投屏採集行為判定為風險事件，該法律風險完全屬於使用者使用第三方遊戲所伴生的既有風險，維護團隊對遊戲運營商的檢測行為免責。

維護團隊在此向所有安全審計機構、程式碼審計員及廣大使用者作出鄭重宣告：本軟體的全部影象處理演算法與模型呼叫邏輯，均接受全社會的公開開源監督。程式碼中不存在任何針對人臉識別資料、身份證文字、信用卡卡號進行定向爬取與隱秘竊取的惡意規則，全套視覺識別體系的唯一技術指向，即為手機遊戲介面的標準 UI 控制元件與關卡文字。

16. 嵌入式 WebUI、WebSocket 閘道器與本地 IPC 通訊安全防護體系
16.1 【本地 Web 控制檯網路拓撲與安全防護定位】
本軟體整合了基於現代化前端框架構建的本地 WebUI 互動控制檯，以及基於 Python aiohttp / FastAPI 架構構建的後端 RESTful 與 WebSocket API 閘道器。該 Web 架構旨在向使用者在移動裝置螢幕上提供現代化觸控配置互動介面。維護團隊就係統內部通訊安全與資料隱私披露如下：
  ▶ （1）預設迴環網路閉環繫結（127.0.0.1）：在預設安全配置下，本軟體內建的 Web 守護程序被嚴格配置為僅監聽在本地迴環網路介面（Loopback Interface, 127.0.0.1:25548）。該網路介面是作業系統核心內部的一套純軟體虛擬網路層，其產生的一切 TCP 報文與 WebSocket 資料幀僅在裝置實體記憶體中被直接短路轉發，完全不經過裝置外部的物理網絡卡晶片（Wi-Fi 或蜂窩天線）。這意味著，在外部區域網或公網上的任何其他裝置，在物理上均無法探測到該埠的存在，亦絕對無法向該回環埠傳送任何網路報文；
  ▶ （2）雙重身份認證防火牆（Token-Based Authentication）：為了防止裝置上安裝的其他惡意第三方應用利用同一區域網迴環許可權擅自呼叫控制介面，本軟體設計了極其嚴密的身份鑑權體系。所有向 WebUI 閘道器發起的 HTTP 資源請求與 WebSocket 握手建立請求，均必須在請求頭中攜帶高熵值的有效安全令牌（X-Api-Token / Authorization Bearer Token）或透過加密 Session Cookie 校驗。任何未攜帶有效 Token 的非法請求，將被閘道器在握手階段瞬間以 HTTP 401 Unauthorized 狀態碼強制拒絕連線。
16.2 【跨站請求偽造（CSRF）與跨域資源共享（CORS）嚴密防禦】
在移動網際網路環境下，惡意網頁可能試圖誘導使用者在瀏覽器中開啟特定釣魚頁面，並利用該頁面的 JavaScript 指令碼向本地迴環地址（http://127.0.0.1:...）傳送非法的跨域非同步請求，試圖竊取本地配置或控制軟體。為了徹底封死此類高危網路漏洞，本軟體在 Web 後端閘道器部署了銀行級別的跨域防禦策略：
  ▶ （1）嚴格的 Origin 與 Referer 來源校驗：閘道器會嚴密審查每一個傳入請求的 Origin 請求頭，僅允許來自本軟體內部 WebView 元件（如特定 Android 內部協議頭）或使用者明確配置的受信域名的訪問請求；
  ▶ （2）禁止憑據跨域共享：閘道器強制關閉了針對非受信域名的 Access-Control-Allow-Origin 萬用字元支援，嚴格禁止瀏覽器在跨域場景下傳遞敏感身份憑據；
  ▶ （3）WebSocket 握手來源阻斷：在建立實時日誌流與狀態推送的雙向 WebSocket 連線時，閘道器會嚴格比對握手報文的來源地址，徹底攔截來自外部惡意網站發起的非法 WebSocket 劫持連線（CSWSH 攻擊）。
16.3 【本地程序間通訊（IPC）機制與資料安全通道】
本軟體由 Android 原生宿主應用程序（Kotlin）與 PRoot 容器內部的 Python 自動化程序兩個獨立執行實體協同組成。兩層體系之間的本地通訊採用了高度隔離且可信的 IPC 資料通道：
  ▶ （1）標準輸入輸出管道守護（Stdin/Stdout Pipe）：宿主程序透過底層標準 POSIX 管道向子程序傳送保活脈衝與生命週期終止訊號，管道受 Linux 程序樹許可權嚴格保護，外部未授權程序無法截獲管道內容；
  ▶ （2）本地迴環私有協議加密流轉：宿主應用的前端控制指令與子程序的執行狀態上報，均透過內部自定義的 JSON-RPC 協議在 127.0.0.1 迴環網路中受限傳輸。傳輸的資料結構嚴格限定於任務狀態列舉（如 TaskState.RUNNING）、當前執行輪次計數、報錯文字描述，絕不包含任何系統級敏感資料或使用者真實身份隱私。
16.4 【WebUI 前端本地靜態資源安全性審查】
嵌入於本軟體內部的 Web 網頁前端靜態資源（涵蓋 HTML 骨架、CSS 樣式表、編譯後的 JavaScript 打包產物、字型庫及 SVG 圖示），全部隨軟體安裝包以離線靜態資產形式內建在本地儲存中。在使用者使用本軟體自帶的 WebView 介面進行操作時：
  ▶ （1）純離線載入與零外部 CDN 指令碼依賴：所有的 JS 庫（如 Vue / React / Tailwind 等前端框架程式碼）均直接從裝置本地磁碟載入解析，絕對不動態從外部商業 CDN 加速節點遠端載入任何可能被中間人篡改或帶有追蹤程式碼的第三方外部指令碼；
  ▶ （2）內容安全策略（Content Security Policy, CSP）防護：Web 頁面部署了嚴苛的 CSP 響應頭規則，禁止頁面動態執行任何未經雜湊驗證的內聯指令碼（unsafe-inline），禁止從外部不可信域名載入圖片或發起非同步請求，全面抵禦跨站指令碼攻擊（XSS）。
16.5 【區域網開放控制模式下的傳輸加密與防暴力破解】
當使用者根據自身管理需要，在軟體設定中主動開啟“區域網控制（LAN Control）”並將監聽繫結至 0.0.0.0 時，本軟體自動提升安全防禦等級：
  ▶ （1）IP 訪問頻率限制（Rate Limiting）：閘道器內建了基於記憶體漏桶演算法的請求限流器，對來自同一區域網 IP 地址的未授權試探請求實施嚴密的頻率限制。一旦檢測到特定 IP 在 1 分鐘內連續出現 5 次以上的 Token 密碼認證失敗，系統將自動將該區域網 IP 關入黑名單封鎖 15 至 60 分鐘，從根本上粉碎駭客利用密碼字典實施的暴力破解攻擊；
  ▶ （2）密碼強雜湊儲存：使用者設定的 Web 控制密碼絕不以明文形式落盤儲存，而是經過密碼學安全單向雜湊函式（如加鹽 bcrypt 或 Argon2 演算法）計算後儲存其雜湊摘要值。即使本地配置檔案遭遇極端物理洩露，外部攻擊者亦無法在有限時間內反向逆推明文密碼。
16.6 【遠端穿透會話（Remote Session）的狀態隔離與斷線銷燬】
在遠端訪問高階模式下，為了防範會話被重放或長久滯留，本軟體建立了嚴格的會話生命週期時效機制：
  ▶ （1）短期有效期與動態重新整理：遠端訪問發放的臨時管理憑證被設定了合理的生命週期限制，超時未活動將自動強制登出會話；
  ▶ （2）一鍵終止遠端活躍連線：使用者在手機本地介面中隨時可點選“終止所有當前網路會話”，閘道器將瞬間強制切斷並關閉所有當前處於連線狀態的外部遠端 TCP 與 WebSocket 通道，立即令所有的外部遠端控制端強制下線。
16.7 【網路狀態監聽的隱私極小化】
本軟體申請並在後臺監聽裝置網路狀態變化（ACCESS_NETWORK_STATE），其唯一用途在於感知當前網路是否由家庭受信任 Wi-Fi 切換為了移動蜂窩網路，以便在網路變動時向使用者彈出提示，防止在未知網路環境下繼續暴露區域網埠或意外消耗手機高額蜂窩流量。本軟體絕不利用網路監聽介面蒐集周圍環境中的 Wi-Fi 路由器 BSSID、SSID 廣播名稱或基站小區識別碼，絕不利用網路環境蒐集使用者的粗略或精確物理地理位置。
16.8 【Web 架構純粹性與開原始碼可審計性承諾】
維護團隊再次向使用者莊重宣告：本軟體內建的整個 Web 服務與通訊中介軟體體系，完全基於公開、成熟、經過全球數百萬開發者廣泛審計的標準開源元件構建。系統內部絕不包含任何用於商業資料收集的私有跟蹤協議，絕不向任何商業雲平臺回傳控制日誌。使用者完全擁有在本地徹底關閉 Web 服務的絕對自由。

17. 自動化狀態機、業務排程流水線與遊戲資產相關引數的本地脫敏治理
17.1 【有限狀態機（FSM）排程引擎之資料流轉脫敏原理】
本軟體驅動遊戲執行全流程的核心，是一套極其龐大、嚴密的有限狀態機（Finite State Machine, FSM）業務排程引擎。狀態機引擎在不斷迴圈的“捕獲影象 -> 匹配當前介面狀態 -> 決策下一步操作 -> 派發觸控事件 -> 等待響應”的閉環狀態鏈條中運作。維護團隊深入貫徹資料治理中的“隱私設計（Privacy by Design）”工程哲學，確保狀態機在全流程中的所有業務引數流轉均實施嚴格的本地脫敏隔離。
17.2 【出擊與戰鬥排程模組的資產脫敏規範】
在執行主線關卡、困難戰役、限時活動出擊任務期間：
  ▶ （1）遊戲關卡引數本地解析：關卡代號（如 7-2、12-4、13-4、SP4 等）僅作為純文字字串在記憶體排程佇列中匹配預設的座標尋路網格，絕不與任何外部使用者身份資訊進行繫結；
  ▶ （2）艦隊編制資料無痕流轉：出戰艦船的角色編號、艦船等級僅用於判定是否滿足出戰門檻與心情閾值，相關狀態資料完全停留在 RAM 記憶體變數中，在戰鬥結束結算並返回港區後立即被垃圾回收機制（GC）清理，不構建長久儲存的艦隊資產編成履歷資料庫；
  ▶ （3）掉落物品結算本地化：戰鬥勝利後介面掉落的新艦船、裝備圖紙、物資獎勵由 OCR 模組進行瞬時識別並計數，其計數結果僅用於在 WebUI 面板上展示臨時的“本次執行收益統計”。該統計資料屬於易失性資料，軟體關閉後即刻歸零，絕不向任何外部伺服器上報使用者的歐氣抽卡機率或掉落明細。
17.3 【演習與競技場模組的戰力資料瞬時銷燬】
在演習對手篩選過程中，演算法從演習介面提取的四個對手的遊戲暱稱、對手防守艦隊旗艦立繪、以及對手錶面顯示的戰力數值，其處理嚴格遵循“用完即棄”準則：
  ▶ （1）戰力對比排序在本地記憶體完成，用於引導點選座標定位至最容易擊敗的對手；
  ▶ （2）對手的暱稱與 UID 絕對不記錄在任何持久化磁碟日誌檔案中，防止在日誌匯出時不慎洩露其他第三方法定玩家的遊戲身份與隱私；
  ▶ （3）演習挑戰完成後的勝負積分統計，僅作為當前賽季本地進度的臨時指示器，不作雲端持久化歸檔。
17.4 【軍事委託與戰術學院模組的隱私安全隔離】
在自動化派遣軍事委託與戰術學院技能學習任務中：
  ▶ （1）空閒艦船匹配演算法完全在裝置本地離線執行，僅根據船塢中艦船的稀有度標籤、特定艦種（驅逐、輕巡、重巡、戰列、航母）進行邏輯過濾；
  ▶ （2）技能教材的消耗計數（如紅色 T3 教材消耗數、黃色 T2 教材消耗數）僅用於更新本地任務執行狀態卡片，絕不將使用者的道具庫存餘量向任何外部第三方披露；
  ▶ （3）本軟體絕對禁止在委託與學院模組執行任何帶有真實貨幣或付費鑽石消耗屬性的自動化分支，從底層邏輯設計上斬斷任何涉及財產處分的資料處理風險。
17.5 【後宅與貓窩養成模組的資料最小化】
在後宅管理中，後宅五位休息艦船的好感度愛心氣泡點選、食物存糧百分比監視、以及指揮喵餵養操作：
  ▶ （1）艦船好感度狀態（失望、普通、好感、誓約等狀態）僅作為是否允許出擊的布林值邏輯條件進行本地比較，不上傳、不歸檔；
  ▶ （2）後宅舒適度數值、傢俱擺放座標完全屬於客戶端本地圖形表現，本軟體不提取、不記錄後宅傢俱的佈局資料；
  ▶ （3）指揮喵的天賦詞條文字在本地完成匹配判斷後立即銷燬，不向外部洩露使用者極品指揮喵的詞條配置機密。
17.6 【大型作戰（大世界）沙盤探索的座標與資產保護】
大世界包含極其複雜的二百餘個獨立海域節點、塞壬要塞、深淵首領戰以及港口補給體系：
  ▶ （1）海域座標記錄儀使用量、大世界行動力點數餘量、港口代幣數量等關鍵資料，僅由狀態機用於維持尋路與港口掃貨邏輯，絕不對外同步；
  ▶ （2）信標·META 戰鬥中的助戰請求觸發完全透過模擬遊戲內的官方“請求公會/好友助戰”原生按鈕實現，本軟體自身不搭建任何私有的跨玩家助戰通訊網路，助戰資料流完全走遊戲官方正規伺服器通道，本軟體不攔截亦不窺視助戰隊友的個人資訊。
17.7 【軍部科研室研發藍圖與魔方閾值的本地防洩漏】
在軍部科研室專案排程中，心智魔方剩餘存量、物資儲備量是事關玩家賬號戰略安全的核心資產引數：
  ▶ （1）本軟體在本地透過 OCR 讀取的主介面金幣數與魔方數，僅用於同使用者在配置中親自設定的“安全保留底線”（例如“魔方低於 200 個時禁止接受魔方科研”）進行閾值比較；
  ▶ （2）比較邏輯在 CPU 暫存器級別瞬時完成，相關數值不寫入任何可被外部提取的公開文字日誌中，堅決保護使用者的真實遊戲財富狀況不受第三方窺探。
17.8 【本地配置引數匯出時的敏感資料淨化處理】
當使用者選擇使用本軟體內建的“匯出我的配置模板”以便將自身優秀的任務流程分享給其他社群群友或在多臺裝置間共享時，系統內建的匯出過濾器會自動觸發敏感資料淨化機制：
  ▶ （1）自動剔除全部網路訪問密碼與身份 Token；
  ▶ （2）自動剔除無線除錯配對私鑰及裝置專屬標識；
  ▶ （3）自動將與個人賬號深度繫結的特定過濾白名單進行脫敏提示；
  ▶ （4）確保使用者匯出的分享配置檔案僅保留純粹通用的遊戲任務排程邏輯，從源頭切斷因使用者主動分享配置導致的個人隱私連帶洩露隱患。

18. 常見作業系統定製版許可權與隱私沙箱深度適配說明
18.1 【國內主流廠商定製 ROM 隱私架構的特殊性】
中國大陸市場 Android 移動生態具有極度碎片化與高度定製化的技術特徵。各大手機硬體廠商在其自主研發的深度定製作業系統中（包括小米 HyperOS/MIUI、華為 HarmonyOS、OPPO ColorOS、vivo OriginOS、榮耀 MagicOS 等），普遍推行了一系列遠超 Google 原生 Android 標準的激進型隱私保護機制與許可權管控框架。本軟體在架構設計上充分尊重、深度適配並嚴格遵循各大廠商的定製隱私規範，絕不透過駭客技術手段嘗試破壞或繞過廠商的系統隱私防線。
18.2 【小米 MIUI / Xiaomi HyperOS 隱私防護特性深度適配】

為了防止在原始碼與最終分發給使用者的 APK 安裝包之間發生“中間人惡意程式碼注入”或編譯機投毒風險，本軟體在工程設計上積極對齊“可重現構建”標準：

  ▶ （2）自動化漏洞依賴掃描（Dependabot）：官方倉庫配置了自動化的依賴項漏洞掃描機器人，一旦上游依賴庫被國家脆弱性資料庫（NVD）或 GitHub Advisory Database 披露存在已知的 CVE 安全漏洞，流水線會第一時間發出警報並督促維護團隊完成升級替換。

本軟體在日常開發構建流程中深度整合了多維度的靜態程式碼安全檢查（Lint）工具與記憶體安全準則：

  ▶ （2）C++ 記憶體安全準則：在 Native 橋接層嚴密遵循現代 C++17 智慧指標（std::unique_ptr / std::shared_ptr）與 RAII 資源管理哲學，全面杜絕雙重釋放（Double Free）、釋放後使用（Use After Free）、以及基於堆疊的緩衝區溢位（Buffer Overflow）漏洞；

21. 個人資訊保安生命週期審計、去標識化雜湊流轉與終端防禦深度指引
21.1 【資料全生命週期安全審計閉環】
依據國家關於資料安全治理的行業標準規範，本軟體將個人資訊在移動裝置本地的處理流程細分為“產生 - 採集 - 傳輸 - 儲存 - 使用 - 銷燬”六大完整階段，並在每一個獨立階段構建起堅實的密碼學與工程學技術防禦壁壘：
  ▶ （1）產生與採集階段：嚴格恪守使用者明示授權原則，非授權不採集，非執行態不啟用投屏與輸入通道；
  ▶ （2）傳輸階段：所有程序間通訊（IPC）與容器內部資料流轉僅限於本地系統內部虛擬匯流排，網路遠端訪問全程採用 TLS 1.3 / SSH-2 行業高強度加密隧道；
  ▶ （3）儲存階段：資料 100% 封閉在 Linux 私有沙箱內部，敏感金鑰排除系統雲備份；
  ▶ （4）使用階段：記憶體資料即時計算，絕不構建任何違背使用者初衷的商業畫像與統計模型；
  ▶ （5）銷燬階段：日誌輪換自動清理、臨時影象隨退即焚、應用解除安裝物理扇區全面抹除。
21.2 【去標識化雜湊演算法在資料診斷中的實踐】
為了在向開源社群報告複雜技術故障時最大程度保護使用者的數字人格與隱私權，本軟體在生成內部診斷快照時，引入了基於 SHA-256 密碼學雜湊函式的單向去標識化機制。系統自動將部分偶發出現的裝置內部識別符號轉化為不可逆的固定長度雜湊摘要（如 hash("device_id_salt") -> a1b2c3d4...）。該摘要僅作為區分不同測試裝置的臨時符號，外部任何機構均無法依據該雜湊摘要反向逆推使用者的真實硬體引數或個人身份。
21.3 【跨程序共享記憶體（Shared Memory）的訪問許可權收緊】
在 Native 橋接層與 Java/Kotlin 宿主層之間傳遞大容量螢幕幀影象時，本軟體採用 Android 底層標準 ashmem（Android Shared Memory）或 Linux memfd 匿名檔案控制代碼。維護團隊在程式碼底層對該共享記憶體控制代碼設定了極其嚴厲的保護標誌：
  ▶ （1）僅允許宿主應用程序與其合法派生的特權 app_process 子程序透過 Binder IPC 傳遞該檔案描述符（File Descriptor, FD）；
  ▶ （2）記憶體區域被設定為只讀（PROT_READ）共享，防止子程序意外篡改原始圖形資料；
  ▶ （3）外部任何未持有合法 Binder 令牌的第三方惡意程序，在作業系統核心級別均被禁止對映該共享記憶體段，有力捍衛了畫素流的記憶體級機密性。
21.4 【針對側通道攻擊（Side-Channel Attack）的防禦機制】
在極端高對抗的安全威脅模型下，駭客軟體可能嘗試透過監視裝置的 CPU 瞬時功耗曲線、快取命中率（Cache Miss Rate）或特定系統廣播的時序差，推斷當前遊戲螢幕是否發生了特定變化（即所謂的微架構側通道攻擊）。本軟體的狀態機引擎在排程演算法中引入了時間維度的平滑緩衝與虛假操作填充（Dummy Operation），使得整體計算任務的 CPU 負載呈現平緩的均勻分佈，極大增加了外部側通道分析的訊雜比與破解難度。
