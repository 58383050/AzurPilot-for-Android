1. 术语定义与个人信息分类界定
1.1 【个人信息之定义】
依据《中华人民共和国个人信息保护法》第四条之规定，个人信息是以电子或者其他方式记录的与已识别或者可识别的自然人有关的各种信息，不包括匿名化处理后的信息。
【涉及数据范畴界定】：
在本软件的技术运行语境下，可能涉及的个人信息范畴包括但不限于：
  ▶ 游戏角色昵称与数字 UID（若在调试截图或异常排障日志中显现）；
  ▶ 设备底层硬件特征标识符（在排障诊断日志中显现）；
  ▶ 无线调试（ADB）连接密钥与本地控制口令；
  ▶ 包含在自动化截屏缓存中的部分可能关联到个人身份的文字或视觉画面信息。
1.2 【敏感个人信息之定义——核心敏感凭证防护】
依据《中华人民共和国个人信息保护法》第二十八条之规定，敏感个人信息是一旦泄露或者非法使用，容易导致自然人的人格尊严受到侵害或者人身、财产安全受到危害的个人信息，包括生物识别、宗教信仰、特定身份、医疗健康、金融账户、行踪轨迹等信息，以及不满十四周岁未成年人的个人信息。
【核心敏感凭据防护范畴】：
在本软件中，以下数据依法被纳入敏感个人信息的最高等级防护范畴，实施物理隔离与严密保护：
  ▶ 设备锁屏指纹 / 面容认证交互结果（仅单向接收系统布尔值，绝不接触生物原始数据）；
  ▶ 无线调试（Wireless Debugging）RSA 配对私钥（adbkey）与配对鉴权 Token；
  ▶ 局域网及远程控制访问密码、身份校验 Token。
1.3 【去标识化与匿名化】
去标识化是指个人信息经过处理，使其在不借助额外信息的情况下无法识别特定自然人的过程；匿名化是指个人信息经过处理无法识别特定自然人且不能复原的过程。
【处理原则与技术措施】：
  ▶ 本软件在生成错误诊断日志及数据导出包时，竭力贯彻去标识化设计，力求抹除直接可读的个人敏感属性；
  ▶ 对可能出现的敏感标识符实施脱敏掩码，杜绝未经授权的逆向关联分析。
1.4 【本地私有目录与应用沙箱】
指 Android 操作系统基于 Linux 文件系统权限模型，为本软件专属分配的独立存储空间（通常物理路径为 /data/user/0/com.azurpilot.ghio/）。
【沙箱安全边界】：
  ▶ 该目录受操作系统内核级 SELinux 强制访问控制策略与 UID/GID 权限隔离保护；
  ▶ 在默认非 Root 环境下，设备上安装的其他任何普通第三方应用均被物理阻绝在外部，绝对无法跨目录读取本软件私有目录中的任何文件。
1.5 【嵌入式 PRoot 容器环境数据】
指解压并驻留于本软件私有存储目录中的轻量级 Ubuntu Linux 根文件系统（Rootfs）。
【容器环境资产构成】：
  ▶ 该容器环境包含独立的 /etc、/usr、/var 目录体系、Python 3 运行库及上游 AzurPilot 自动化代码库；
  ▶ 容器内的全部数据与文件，在宿主操作系统视角下均完整归属于本应用的私有内部数据，完全受到应用沙箱保护。
1.6 【运行诊断日志与系统堆栈数据】
指本软件在运行过程中由 Timber 日志框架以及 Python 内置 logging 模块向设备物理闪存中写入的文本流水记录。
【诊断日志包含信息】：
  ▶ 系统初始化时序、组件启动状态、JNI 底层调用耗时；
  ▶ 图像模板匹配得分、任务状态机跃迁步骤；
  ▶ 在发生未捕获异常时的完整崩溃堆栈跟踪（Crash Stacktrace），用于故障定位与排查。

2.2 【设备硬件与系统诊断数据】
为了在碎片化严重的 Android 设备生态中评估硬件兼容性、适配特定厂商定制 ROM 的特殊机制、并辅助用户进行运行时故障排除，本软件会在设备本地读取部分设备软硬件基础特征，并在发生异常时输出至本地诊断日志中。该等信息包括：
  ▶ （1）设备基本物理型号：
      a. 设备制造商名称（Build.MANUFACTURER，如 Xiaomi、HUAWEI、OPPO、vivo、Samsung 等）；
      b. 设备商业品牌（Build.BRAND）；
      c. 产品型号代码（Build.MODEL）。
  ▶ （2）操作系统与底层内核版本：
      a. Android 操作系统版本号（Build.VERSION.RELEASE，如 Android 13、14、15）；
      b. 系统 API 级别（Build.VERSION.SDK_INT）；
      c. 底层 Linux 内核版本号；
      d. 系统安全补丁程序日期（Build.VERSION.SECURITY_PATCH）。
  ▶ （3）CPU 处理器架构与硬件特征：
      a. 设备支持的 ABI 架构列表（Build.SUPPORTED_ABIS，如 arm64-v8a、x86_64）；
      b. CPU 核心数量、运行频率及大小核拓扑结构。
  ▶ （4）显示与窗口度量参数：
      a. 物理屏幕宽度与高度像素值；
      b. 逻辑像素密度（DPI / Density）；
      c. 屏幕刷新率（Hz）；
      d. 系统安全区域内边距（DisplayCutout / Insets）及导航栏高度。
  ▶ （5）内存与电池实时状态：
      a. 系统总物理内存（Total RAM）与当前可用内存水线；
      b. 电池当前电量百分比、健康度状态、充电状态与机身电池温度。
维护团队庄严保证：读取上述设备信息纯粹系为本地技术兼容性判定（例如动态决定采用何种 ABI 版本的 PRoot 动态库、是否需要针对特定 ROM 开启防冻结看门狗、是否需要压暗屏幕亮度），本软件绝不利用上述数据拼接生成任何用于设备追踪的“设备唯一指纹”，亦绝不将上述数据上传至任何分析平台。

2.4 【屏幕图像捕获与临时图像缓存处理】
为了实现自动化操作所必需的视觉感知能力，本软件在得到用户明确授权的前提下，通过底层图形管线（MediaProjection 或 VirtualDisplay）连续捕获设备屏幕的实时画面。在图像数据的全生命周期流转中，本软件贯彻如下极度严格的隐私保护机制：
  ▶ （1）内存即时流转与零落地：屏幕采集模块将截屏像素阵列以位图形式直接载入 RAM 共享内存中，供 OpenCV 模板匹配引擎进行像素比对。在绝大多数正常运行场景下，这些图像帧数据在完成比对判定后立即在内存中被下一帧覆盖释放，绝不写入物理存储介质（ROM/Flash）；
  ▶ （2）受限排障截图落盘机制：当且仅当发生严重识别死锁、连续数次超时未匹配到目标锚点、或用户在设置中主动开启了“保存错误排障截图”选项时，系统才会将发生错误当下的瞬时画面以 PNG/JPG 格式短暂写入私有存储的 debug/ 临时目录中，用于辅助用户排查为什么特定界面未能被正确识别；
  ▶ （3）排障截图之敏感内容预警：
      a. 游戏画面截图中不可避免地会包含展示在游戏 UI 上的游戏角色昵称、玩家个性签名、大舰队公会名称、聊天气泡内容、甚至在游戏顶栏展示的虚拟财产余额。本软件郑重承诺绝不对该等截图进行任何形式的云端自动同步；
      b. 用户在后续使用日志导出功能时，有绝对责任自行检查并删除该等图片。
2.5 【OCR 文字识别与内存即时擦除机制】
本软件内置的 LiteRT OCR 神经网络推理模块用于识别关卡名称、数字金额、剩余油量及角色姓名。OCR 推理完全在移动设备的 CPU / NPU 硬件加速器本地运算，其输入的图像切片及输出的 Unicode 文本字符在完成状态机条件判定后，变量立即在内存中被回收，不构建任何长久保存的历史文本数据库。
2.6 【无线调试（ADB）配对密钥与凭证——核心敏感凭证防护】
在免 Root 且未安装 Shizuku 的特定设备上，为了通过 Android 11+ 内置的“无线调试”（Wireless Debugging）通道启动底层守护进程，本软件需要生成并存储一套专属的 RSA-2048 非对称加密密钥对（adbkey 与 adbkey.pub），并在配对过程中保存配对端口与鉴权 Token。
  ▶ （1）密钥存放安全级别：该 RSA 密钥对安全生成并存放在应用的私有加密偏好目录中，其权限受到 Linux 系统文件级别严格保护；
  ▶ （2）系统云备份显式物理排除（核心安全防线）：为了防止该高敏感的 ADB 调试控制密钥随手机厂商的系统云备份或整机换机迁移被克隆泄露至第三方云端，本软件在工程清单（AndroidManifest.xml 及 backup_rules.xml / data_extraction_rules.xml）中将其列为绝对排除项，确保该密钥物理孤立在当前单一设备内部。
2.7 【本地 WebUI 访问控制密码与访问令牌——敏感凭证防护】
为了向用户提供基于网页的直观管理控制台，本软件内置了轻量级 Web 服务器。为了防止设备上安装的其他恶意应用通过回环网络（127.0.0.1）擅自发起非法控制请求，本软件在首次初始化时会自动生成高熵值的随机身份认证令牌（Token）或由用户亲自设定控制密码。该凭据安全持久化于私有配置中，每次 HTTP / WebSocket API 请求均须强制核验该凭据，以此构筑本地进程间通信的安全防火墙。
2.8 【局域网通信与远程穿透访问数据】
当用户在设置中主动开启“局域网控制”或“远程访问”高级网络扩展功能时：
  ▶ （1）局域网通信流转：本软件的 WebUI 监听端口向当前局域网开放，传输的内容包含控制台 HTML/JS 静态资产、控制指令 JSON 报文、以及实时的屏幕预览 JPEG 图像流。所有数据仅在您局域网内部的控制端与被控端设备之间进行对等传输；
  ▶ （2）远程穿透隧道数据：通过基于 SSH 反向隧道或点对点 P2P 穿透技术，数据流经外部中继跳板。在此类场景下，网络中转节点仅作为无状态的数据包路由转发管道，传输信道采用标准 TLS / SSH 加密协议封装，维护团队不设立任何用于解密、窥探、窃听或记录用户控制流量内容的中心监控节点。
2.9 【崩溃日志、异常堆栈与诊断信息】
当应用程序发生意外崩溃、ART 虚拟机抛出未捕获异常、或底层 JNI 链接库触发 SIGSEGV 段错误信号时，Android 系统的崩溃捕获机制及 Timber 日志记录器会将当下的线程调用栈（Call Stack）、发生异常的代码行号、错误描述写入本地 crash_log.txt 文件中。该文件完全停留在用户本地磁盘中，本软件绝对不部署任何后台自动向维护团队静默上传崩溃日志的隐蔽上报服务。全部日志的向外提供，必须依赖用户本人的百分之百主动手动操作。

3. 设备系统权限的调用规范与用户动态控制机制
3.1 【系统权限申请的最小化与必要性原则】
依据《中华人民共和国个人信息保护法》第五条所确立的“处理个人信息应当具有明确、合理的目的，并应当与处理目的直接相关，采取对个人权益影响最小的方式”之法律准则，本软件在权限架构设计上秉持极其严苛的克制态度。我们绝不申请任何超出自动化运行技术所绝对必需的权限。对于通话记录、联系人、短信、GPS 位置、相机、麦克风等高度敏感且与业务无关的权限，本软件在代码清单（AndroidManifest.xml）中实施了物理排除，自始至终绝不申请。
3.2 【屏幕录制与投屏权限（MediaProjection）——重点核心权限】
  ▶ （1）权限申请之业务必要性：当用户选择免 Root 的标准投屏模式运行本软件时，本软件必须借助 Android 系统的 MediaProjection 框架建立屏幕镜像虚拟显示层，以便本地计算机视觉算法能够逐帧读取当前屏幕上的像素矩阵，识别游戏主界面、关卡按钮及战斗结算图标；
  ▶ （2）权限调用的时机与用户显式交互：该权限无法在应用安装时静默获取。每次用户点击启动自动化任务时，系统会弹出全局系统级安全确认对话框（“AzurPilot 将开始截取您的屏幕上显示的所有内容”）。用户必须亲自在系统弹窗中点击“立即开始”或勾选“本次允许”，本软件方可合法接收系统的 VirtualDisplay 句柄；
  ▶ （3）权限使用边界与安全承诺：维护团队郑重声明：该权限仅在自动化任务处于“运行中”状态时被激活，且捕获的屏幕数据流仅用于本地内存中的模式匹配计算与临时排障缓存，本软件绝对不将录屏流进行后台录像、绝不进行任何云端直播推流、亦绝对不将屏幕像素发送至任何商业服务器；
  ▶ （4）权限撤回途径：
      a. 用户可随时通过点击本软件通知栏上的“停止”按钮、按下悬浮窗停止键终止录屏；
      b. 亦可在 Android 系统“设置 - 应用管理 - 特殊应用权限 - 投屏/录屏”中彻底撤销该项授权。
3.3 【系统无障碍服务权限（AccessibilityService）——重点核心权限】
  ▶ （1）权限申请之业务必要性：在非 Root、非 Shizuku 环境下，为了实现自动模拟点击、滑动及手势操作，本软件需要依赖 Android 操作系统提供的无障碍服务（com.azurpilot.ghio.service.AppAccessibilityService）。无障碍服务提供了系统级的手势分发接口（dispatchGesture），允许应用向窗口管理器安全地注入虚拟触控手势；
  ▶ （2）安全边界与防窥私承诺：
      a. Android 无障碍服务通常具备极高的监听能力。维护团队在此向所有用户做出最为郑重的合规保证：本软件的无障碍服务实现代码严格保持技术纯洁性，绝不注册任何监听窗口内容变化、监听按键事件（OnKeyEvent）、读取屏幕 UI 节点树文本（AccessibilityNodeInfo）的回调逻辑；
      b. 本软件绝不利用无障碍服务窥探用户在任何第三方应用（如社交软件、电子邮箱、银行网银、备忘录）中输入的任何文字信息、绝对不窃听密码键盘。
  ▶ （3）权限撤回途径：用户可随时进入 Android 系统的“设置 - 辅助功能 / 无障碍 - 已安装的应用 - AzurPilot”，手动将无障碍开关切换为关闭状态。关闭后，本软件将立即失去手势注入能力并安全终止运行。
3.4 【显示在其他应用上层权限（SYSTEM_ALERT_WINDOW）】
  ▶ （1）业务必要性：为了向用户提供便捷的一键启停控制入口、实时展示当前自动化任务的执行状态（如当前执行轮次、剩余石油量、当前关卡名称），并在游戏画面卡死时向用户呈现紧急停止控制柄，本软件需要申请系统悬浮窗权限；
  ▶ （2）权限调用的独立性：用户享有完全自主的选择权，若用户不希望在屏幕上看到常驻悬浮控制球，可以在应用设置中将其关闭，或者在系统设置中撤销悬浮窗权限。撤销该权限仅导致悬浮卡片无法展示，不影响底层自动化任务通过通知栏进行的后台静默运行。
3.5 【常驻前台服务权限（FOREGROUND_SERVICE）】
  ▶ （1）业务必要性：依据 Android 9.0（API 28）至 Android 15（API 35）的后台运行合规规范，任何需要在后台持续运行而不被系统省电策略瞬间冻结挂起的服务，必须显式声明前台服务并在系统通知栏持久展示具有高优先级的常驻通知（Ongoing Notification）；
  ▶ （2）通知栏信息展示内容：本软件的前台服务通知清晰明了地展示了当前应用的运行状态（如“AzurPilot 正在后台运行”、“当前任务：主线出击”），并内置了“暂停”、“停止”等即时操作动作，确保用户对后台进程的存在保持时刻清醒的知情权与绝对控制力；
  ▶ （3）权限类型细分合规：本软件严格依照 Google 最新平台规范，根据具体场景细分声明了 FOREGROUND_SERVICE_MEDIA_PROJECTION（用于投屏服务）、FOREGROUND_SERVICE_SPECIAL_USE（用于容器宿主维持）等特定类型，绝不滥用模糊服务类型规避系统审查。
3.6 【特权提权服务（Shizuku / Root / app_process）——高阶系统特权】
  ▶ （1）高阶架构与特权申请原理：当用户追求极致的运行体验（如在前台使用手机的同时让游戏在完全隔离的第二虚拟屏幕后台静默运行）时，本软件支持与 Shizuku 框架或系统超级用户（Root su 管道）进行 IPC 绑定，进而调用 Android 系统的 app_process 命令行工具启动具有系统级权限的远程特权守护进程（RemoteServiceManager）；
  ▶ （2）特权服务安全边界与代码开源受控：用户知悉向本软件授予 Root 权限或在 Shizuku 授权管理器中批准本软件访问，意味着赋予了特权守护进程调用系统底层隐藏 API 的能力。维护团队在此承诺：该特权进程的所有源代码均在官方仓库完全公开，其功能严格且唯一地局限于：通过 DisplayManager 创建独立虚拟显示屏、通过 WindowManager 在该虚拟屏上启动目标游戏 Activity、通过 InputManager 向该虚拟屏直接派发输入事件。特权进程绝不利用系统超级权限篡改系统分区（/system）、绝不篡改系统只读属性、亦绝不读取其他应用的隐私数据库；
  ▶ （3）特权授权之随时吊销：用户可随时在 Shizuku 客户端中撤销对 AzurPilot 的授权，或者在 Magisk / KernelSU / APatch 等 Root 管理器中一键关闭对本软件的超级用户授权。
3.7 【生物识别与安全锁认证接口（USE_BIOMETRIC）】
  ▶ （1）业务必要性：为了协助用户保护存放在本地的敏感配置、防止家人、同事或他人在无意接触用户手机时擅自调起本软件或篡改任务参数，本软件提供了可选的“应用安全锁”功能；

3.8 【网络通信权限（INTERNET 及网络状态查询）】
  ▶ （1）业务必要性：本软件申请 android.permission.INTERNET、android.permission.ACCESS_NETWORK_STATE、android.permission.ACCESS_WIFI_STATE 权限，其技术用途严格限定于：从官方公开的开源镜像站下载/更新 Ubuntu PRoot 运行环境归档包、在局域网开启控制台监听、建立远程 SSH/P2P 控制隧道、以及查询当前网络是否处于 Wi-Fi 环境以提示用户避免在移动蜂窝网络下消耗流量；

4. 信息的存储地点、技术保护措施与生命周期管理
4.1 【存储地点：设备本地私有沙箱目录】
依照《中华人民共和国个人信息保护法》第四十条关于个人信息本地化与数据驻留的法理精神，本软件在数据生命周期管理中贯彻最为彻底的“本地化驻留”原则：所有因安装、配置、运行本软件产生的一切用户偏好、配置、运行日志、临时图像、运行环境镜像与密钥凭据，均 100% 保存在设备内部私有存储空间中（/data/user/0/com.azurpilot.ghio/）。本软件不构建任何外部中心化数据中心，绝不存在任何后台静默上传逻辑。
4.2 【Android 系统底层沙箱隔离与访问控制】
本软件充分依托并深度集成 Android 移动操作系统的多层防御安全架构：
  ▶ （1）Linux UID/GID 进程隔离：Android 系统在安装本软件时，为其分配了全系统唯一的 Linux 用户标识符（UID）。在操作系统内核级别，文件系统通过标准的 POSIX 权限位（如 0700 / 0600）将应用私有目录的读写权限严格限制在该专属 UID 对应的进程之内，设备上安装的其他普通应用程序在内核级别被剥夺了访问该目录的权限；
  ▶ （2）SELinux 强制访问控制策略：即便在特定多用户环境或权限提升场景下，操作系统底层的 SELinux 策略规则严格规定了 untrusted_app 域对文件系统标签（Context）的访问规则，防止跨沙箱非法遍历；
  ▶ （3）敏感凭据内存加密与即时擦除：在处理敏感密码、认证 Token 与解密密钥时，本软件优先采用可安全擦除的字符数组（char[] / byte[]）而非不可变的字符串（java.lang.String）进行内存持有，在凭证验证通过后第一时间使用零值覆写内存区域，降低通过读取内存镜像（Memory Dump）窃取敏感凭证的技术风险。
4.3 【敏感配对密钥排除系统云备份机制——核心安全防线】
  ▶ （1）系统云备份之泄露隐患：
      a. 当前主流智能手机操作系统（如 Google 原生 Android、小米 MIUI/HyperOS、华为 EMUI、OPPO ColorOS 等）普遍内置了便捷的“整机云备份”与“一键换机助手”功能。当用户开启云备份后，系统默认会将应用私有目录中的共享首选项（SharedPreferences）及数据库无感知同步上传至手机厂商的公有云端服务器。对于普通配置项，这种备份有助于提升换机体验；
      b. 但对于无线调试（ADB）配对密钥、本地鉴权 Token 等敏感安全凭证，一旦随备份同步至厂商云端，极易因云端账号被盗或换机过程中的跨设备传输造成凭证实质性失窃与外泄。
  ▶ （2）严格的云备份隔离规则部署：为了彻底根绝上述安全隐患，本软件依据 Android 官方安全规范，在工程清单中部署了高等级的安全备份规则配置文件（res/xml/backup_rules.xml 以及适配 Android 12+ 的 res/xml/data_extraction_rules.xml）。我们在规则中进行了明确的排除指令配置：显式排除了所有存放 ADB 配对私钥、配对端口历史、控制密码及身份 Token 的文件路径，强制禁止操作系统底层将此类高敏感凭据纳入云端备份或设备间克隆传输流程。用户在更换新手机后，此类凭据必须在新设备上重新安全生成，以此保障旧凭证绝不在网络云端产生任何泄露痕迹。
4.4 【零高频 Flash 写入与内存数据保护】
移动终端的物理闪存芯片（UFS/eMMC）属于耐受性受限的物理存储介质。如果应用程序高频地向磁盘落盘写入大量瞬时数据，不仅会严重缩短手机主板的使用寿命，更会在磁盘未分配簇空间中留下难以彻底擦除的数据碎片残影。本软件在系统架构层面严格执行“零高频 Flash 写入”设计原则：
  ▶ （1）所有由屏幕捕获管线输出的实时高帧率图像数据流，全部严格限制在 RAM 物理内存映射环形缓冲区中流转，在完成 OpenCV 特征比对后直接在内存中执行析构释放，绝不经历“截屏 - 存入磁盘文件 - 再从磁盘读取 - 判定后删除”的陈旧落盘流转模式；
  ▶ （2）Native JNI 桥接层与 PRoot 容器之间通过 Linux 匿名共享内存（ashmem / memfd_create）及本地回环套接字进行高速内存级数据交换，从根本上兼顾了极致的运行效率与物理数据防残留安全。
4.5 【运行日志的自动轮换与存储期限控制】
为了平衡故障排查的必要性与本地磁盘空间的有限性，本软件内置了严密的自动化日志轮换管理系统（Log Rotation Policy）：
  ▶ （1）大小与文件数量上限阈值：单个日志文件被设置了严格的大小上限（通常单个文本日志文件达到 5MB 时立即触发分卷滚动）。系统保留的历史轮换日志文件数量被严格限制在极小阈值之内（默认最多保留最近 3 至 5 卷历史分卷）；
  ▶ （2）先进先出与自动覆盖淘汰：当新日志产生导致日志总容量超出预设限额时，底层的日志维护算法会自动以先进先出（FIFO）原则，物理删除最为陈旧的历史日志文件，确保磁盘空间占用始终被锚定在可控的安全区间之内；
  ▶ （3）存储期限说明：
      a. 在用户正常保留安装本软件的情况下，本地偏好配置保持持久保存，直至用户主动修改或卸载应用；
      b. 运行日志受前述轮换机制控制，在正常使用强度下历史记录的留存生命周期通常不超过 7 至 14 个自然日，随时间推移被新日志安全覆写。
4.6 【临时图像与缓存的即时销毁机制】
在自动化任务执行期间，因特定异常排障需要而短暂写入本地存储的错误现场截图（存储于 debug/ 临时目录），受生命周期清理守护逻辑管控：
  ▶ （1）任务退出自动清空：当用户点击停止任务、或任务正常执行完毕退出时，清理逻辑会自动清空该临时目录中的图像缓存；
  ▶ （2）异常残留的手动释放：若因系统突然断电关机导致临时目录中遗留了部分孤儿图片，用户可在软件界面的“存储与维护”面板中点击“立即清空临时缓存”，一键物理擦除该目录下的全部图像文件。
4.7 【一键清除数据与本地存储彻底销毁】
用户享有随时彻底销毁本软件在设备上留存的一切数据痕迹的绝对控制权：
  ▶ （1）应用内出厂重置：本软件设置面板中提供了“恢复出厂设置并清空全部数据”功能，执行后将同步注销本地全部偏好、删除所有配置文件、递归删除解压的 PRoot Ubuntu Linux 根文件系统树并注销向导状态；
  ▶ （2）操作系统级强力数据擦除：用户亦可随时进入 Android 系统的“设置 - 应用管理 - AzurPilot - 存储占用”，点击“清除存储空间 / 清除全部数据（Clear Data）”。该操作是由 Android 操作系统内核直接执行的原子级物理清理指令，系统将直接在底层文件系统分配表中彻底抹去分配给本软件私有包名目录下的全部物理扇区数据，实现无法逆向恢复的彻底物理销毁。当用户在系统桌面长按图标执行“卸载”操作时，操作系统同样会自动且不可逆地全额抹去上述全部私有存储数据。

7. 日志导出、社区反馈与个人隐私脱敏指引
7.1 【本地日志打包工具（LogExportService）离线机制】
在移动端长期运行中，难免因系统环境变异、厂商内核定制或游戏界面改版引发难以复现的技术疑难 Bug。为了便于用户向开源社区提交诊断依据，本软件内置了专门的“日志与环境导出服务（LogExportService）”。维护团队郑重声明：该服务的工作原理是 100% 离线、本地化的文件归档机制。当您点击“导出日志”按钮时，系统仅在本地后台线程中遍历应用私有目录下的 logs/、debug/ 目录，将最近的文本日志及必要的崩溃日志打包压缩为单个 ZIP 文件，并保存至您手机的本地存储目录（如 /sdcard/Download/）。在此全流程中，绝不包含任何静默向外部服务器上传该压缩包的隐藏网络行为。
7.2 【日志中潜在敏感信息清单（UID/昵称/聊天截图）】
尽管维护团队在日志记录框架（Timber 及 Python logging）中尽量避免将个人隐私写入日志，但由于计算机视觉与自动化任务的复杂性，导出的原始诊断日志包中依然不可避免地可能潜伏着以下具有一定敏感性的个人数据碎片：
  ▶ （1）游戏内身份标识符：在关卡出击、个人信息界面或演习界面的异常截图（PNG/JPG）中，极可能直接显示了用户在目标游戏中的游戏角色昵称、数字 UID（账号唯一识别码）、大舰队（公会）名称、个性签名、秘书舰誓约标识；
  ▶ （2）社交隐私内容碎片：若在游戏运行过程中恰好有游戏内好友私信、世界频道滚屏发言、公会聊天气泡弹出，异常截图可能无意中捕获了该等聊天文本画面；
  ▶ （3）设备软硬件标识碎片：在诊断日志的头部，通常记录了当前手机的型号（如 24129PN74C）、操作系统版本（Android 15）、内核架构、物理屏幕分辨率以及授予本软件的权限清单；
  ▶ （4）本地文件物理路径：日志中可能包含本应用私有存储目录的绝对文件系统路径，在某些特定多开分身系统下，该路径可能包含系统分配的用户编号（如 /data/user/999/...）。
7.3 【用户向公开社区提交 Issue 前的强制脱敏义务】
GitHub Issues、Discussions、开源问答论坛以及公开技术群组，在互联网法律属性上均属于“全网公开、任何人可自由阅览、搜索引擎可深度爬取索引的公共信息空间”。维护团队向每一位准备向社区求助的用户发出最为严肃之法律与安全警示：
  ▶ （1）强制性的自检与脱敏义务：在将导出的日志 ZIP 压缩包上传至 GitHub Issue、贴吧、社交群组前，您负有绝对、排他、不可推卸的第一责任，亲自解压并打开其中的日志文本与图片，对所有潜在敏感内容实施强制性的“脱敏处理”；
  ▶ （2）文本脱敏操作规范：您应当使用文本编辑器打开 log.txt，使用全局查找与替换功能，将日志中出现的真实游戏昵称替换为虚拟代号（如 [REDACTED_NICKNAME]），将真实数字 UID 替换为任意随机数字（如 12345678），将手机型号或具体路径进行必要掩码处理；
  ▶ （3）图片脱敏操作规范：对于 debug/ 目录中随附的截屏图片，您必须使用图片编辑工具，对画面中展示的昵称、UID、聊天文字、充值余额区域打上厚实的马赛克或纯色遮挡色块，或者直接删除与报错无关的多余截图；
  ▶ （4）脱敏未履行之法律责任自负：若用户因自身疏忽大意，未履行脱敏义务便将包含完整游戏 UID、真实昵称或私密聊天画面的原始日志包直接公开上传至公共代码仓库，导致该等数据被别有用心的第三方黑产人员、恶意玩家抓取利用，进而引发游戏账号被恶意举报、人肉搜索、隐私泄露或骚扰的，由此产生的一切精神损害、财产损失与名誉侵害，完全由该失密用户自行全额承担，维护团队及社区贡献者对此概不承担任何责任。
7.4 【严禁公开张贴 Token、密码与私钥之特别警告——核心凭证红线】
维护团队在此设立绝对不可逾越的安全红线：
  ▶ （1）严禁公开无线调试配对私钥：绝对严禁在任何公开场合公开张贴或上传您的 adbkey 私钥文件，泄露该私钥意味着任何处于同一网络环境下的攻击者均可无需授权直接接管您的手机底层 ADB 调试特权；

  ▶ （3）失密应急处置：若您不慎在公开社区提交了包含上述高危凭证的日志，您必须立即在 GitHub 上删除该 Issue，并在手机端立即进入软件设置，点击“重置并重新生成 WebUI Token”，同时在系统开发者选项中关闭并重新开启无线调试以使旧配对失效。
7.5 【公开社区公开信息的防盗用与事后处置局限】
用户知悉：互联网公开空间具有不可控的数据抓取特征。GitHub 仓库的公开数据会被全球各类搜索引擎、公有代码克隆镜像站、Wayback Machine 互联网时光机、以及各类大模型训练数据集进行自动化抓取与持久化快照存档。即便用户在事后删除了其提交的 Issue 或关闭了工单，第三方爬虫早已缓存的静态快照可能在未来数年内依然停留在外部镜像站点中。维护团队对全球第三方爬虫镜像站的行为不具备任何司法管辖权与技术干预力，无法保证彻底抹去已被第三方转储的公开信息。

9. 安全事件应急响应与风险防范预案
9.1 【本地数据泄露与越权访问风险评估】
依据《中华人民共和国数据安全法》以及现代信息安全纵深防御（Defense in Depth）理论模型，尽管本软件自身在代码架构上执行了最彻底的本地沙箱隔离策略，但移动终端的整体安全性高度依赖于宿主设备所处的物理与软件综合环境。维护团队对可能诱发本地数据泄露或凭据失窃的高危外部威胁场景进行专业风险评估，提示用户加强自我防护：
  ▶ （1）Root 越狱设备上的全局提权风险：在已被用户主动刷机获取 Root 最高超级用户权限的 Android 设备上，操作系统的 Linux UID 沙箱隔离屏障已被实质性拆除。任何其他被用户授予了 su 权限的第三方流氓应用、恶意模块（如恶意 Magisk 模块、LSPosed 恶意插件）均可直接凭借 root 身份静默读取本软件内部私有目录下的全部 YAML 配置文件、日志、以及包含访问口令的加密偏好数据库，甚至能够直接向 PRoot 容器内注入恶意二进制木马；
  ▶ （2）设备物理遗失、被盗与非授权物理接触：若用户的移动智能设备在未设置强锁屏密码、或锁屏密码已被第三方获知的情况下发生物理遗失、失窃，或者被他人未经许可物理操作，恶意接触者可直接通过点击图标进入本软件，查看用户的游戏自动化策略、或者通过 USB 数据线连接电脑执行 ADB 备份导出未受保护的配置文件；
  ▶ （3）局域网暴露与弱密码爆破风险：当用户在软件设置中主动开启了“局域网控制”或“远程访问”，且用户设定了极度简单的弱密码（例如“123456”、“admin”）或将带有 Token 的登录链接泄露至公网时，外部网络攻击者可通过自动化脚本进行高频字典爆破，进而远程接管控制台；
  ▶ （4）第三方供应链与不可信插件注入：若用户未从官方 GitHub/CNB 渠道下载本软件，而是轻信某些第三方非官方网站、破解论坛下载了所谓的“修改版”、“内购破姐版”、“免更新版”APK，该非官方安装包极大概率已被黑客实施了反编译重签名、并二次打包植入了窃取隐私的键盘记录木马或恶意远控后门。
9.2 【开源项目安全漏洞应急通报机制（Security Advisory）】
为了有效防范并应对潜在的软件安全漏洞，维护团队建立了规范的开源安全应急响应流程：
  ▶ （1）安全漏洞披露渠道：维护团队在官方 GitHub 仓库开通了符合国际标准的私有安全漏洞通报通道（GitHub Security Advisory / Private Vulnerability Reporting）。任何安全研究员、白帽子黑客或社区用户若发现本软件存在潜在的特权提升、路径穿越、内存溢出或 Token 越权漏洞，可直接通过该私有通道向维护团队提交详细的漏洞复现 PoC，切勿在公开 Issue 中直接公布零日漏洞（0-Day）；
  ▶ （2）漏洞评级与紧急修复（Hotfix）：维护团队在收到安全漏洞预警后，将由核心安全人员在 72 小时内完成漏洞技术复现与危害定级（分为严重 Critical、高危 High、中危 Medium、低危 Low）。对于可能导致本地代码执行或越权控制的严重与高危漏洞，维护团队将立即启动紧急热修复流程，在隔离分支内完成代码修补与回归测试，并在最快时间内向全网推送新版本 APK 及修复补丁；
  ▶ （3）安全通告公开发布：在修复版本正式发布上线的同时，维护团队将在官方仓库主页、Releases 更新日志中公开发布规范的 CVE 安全公告，详尽披露漏洞的成因机理、影响版本范围、以及建议用户采取的安全升级操作，全面保障社区用户的知情权。
9.3 【用户端安全应急处置指南（改密/重置/销毁）】
一旦用户发现自身的移动设备遗失、怀疑访问密码已遭泄露、或者发现本软件出现非用户本人意图的异常自动化操作时，用户应当立即按照如下应急预案采取自救措施：
  ▶ （1）第一时间终止网络服务：立即在手机端下拉顶部通知栏点击停止任务，并进入本软件设置界面，将“局域网控制”与“远程访问”开关彻底关闭，瞬间切断来自外部网络的一切连接通道；
  ▶ （2）立即重置 WebUI 认证 Token：在网络设置面板中，点击“强制重置访问 Token”，系统将立即销毁当前旧的所有安全鉴权 Session 与 Token，生成全新的不可预测的高熵随机密钥，迫使所有旧连接瞬间全部失效；
  ▶ （3）注销无线调试（ADB）授权：进入 Android 系统的“设置 - 开发者选项 - 无线调试”，点击“撤销无线调试授权”，并关闭无线调试开关。该操作将强制使操作系统底层的 ADB 守护进程撤销对本软件 adbkey 的配对信任，从系统底层阻断特权提权通道；
  ▶ （4）终极自毁：若设备遭受不可逆的深度感染，用户应直接在操作系统应用管理中执行“清除应用数据”并卸载本软件，彻底销毁本地一切潜在受污染的文件系统镜像。
9.4 【不可抗力与第三方网络攻击免责】
在适用法律法规允许的最大限度范围内，维护团队对于因黑客恶意攻击、计算机病毒大规模爆发、零日系统内核级漏洞利用、移动设备硬件后门、电信运营商骨干网络瘫痪、以及其他超出维护团队合理技术控制与预见能力的不可抗力事件所导致的个人数据泄露、篡改或灭失，依法免除承担任何形式的民事侵权与损害赔偿责任。
9.5 【安全协同与用户自律守则】
信息安全是一项需要软硬件系统、开发者与使用者多方协同的系统工程。用户承诺履行最基本的数字安全卫生守则：
  ▶ （1）保持移动操作系统处于最新安全补丁状态，及时修补系统内核漏洞；
  ▶ （2）不在公共非受信 Wi-Fi 网络下开启无保护的远程端口；

14. 跨平台运行环境（PRoot Linux）内部文件系统与系统调用拦截数据隐私规约
14.1 【PRoot 用户空间虚拟化与文件系统映射隐私边界】
本软件在 Android 移动端开创性地集成了基于 PRoot 技术的嵌入式轻量级 Ubuntu Linux 容器环境。为了使 Python 自动化引擎与 C/C++ 动态链接库正常运行，PRoot 在用户空间层通过 Linux ptrace 跟踪机制对文件系统路径进行动态虚拟映射与重定向。维护团队就虚拟文件系统内部数据隐私机制披露如下：
  ▶ （1）虚拟根目录的物理隔离：容器内的虚拟根目录（/）在宿主 Android 系统中严格对应于应用私有数据目录下的特定子目录（/data/data/com.azurpilot.ghio/files/rootfs/）。容器内发生的所有文件创建、编辑、编译操作，在物理上均完全局限在宿主分配的沙箱配额之内，绝对不具备突破该目录向 Android 系统根目录（/system、/vendor、/data/system）实施越权读写的能力；
  ▶ （2）宿主存储受限挂载（Bind Mount）：为了实现导入导出配置与日志共享，本软件仅通过 PRoot 的 -b 绑定挂载参数，将宿主应用特定的私有数据目录和经用户明确授权的公共下载目录挂载至容器内部。本软件绝对不将包含用户私人照片的 DCIM 相册目录、微信聊天存储目录、以及系统核心敏感目录强行挂载至容器内部，从架构源头杜绝容器环境对设备全局隐私文件的遍历可能。
14.2 【虚拟 /proc 与 /sys 节点的信息脱敏与伪造机制】
在标准的 Linux 系统中，/proc 与 /sys 虚拟文件系统直接暴露了底层硬件的真实设备信息、CPU 序列号、内核参数、物理网卡 MAC 地址、以及系统中所有运行中进程的完整命令行参数（cmdline）与环境变量（environ）。在 Android 系统中，若普通应用能够随意读取上述节点，将严重危及其他后台应用的运行隐私。为此，本软件在 PRoot 运行时中部署了高度安全的虚拟节点伪造与脱敏机制：
  ▶ （1）设备特征伪造：容器内部读取的 /proc/cpuinfo、/proc/version 节点，均经过了 PRoot 的本地静态模拟或脱敏过滤，不读取包含真实硬件序列号的底层物理寄存器；
  ▶ （2）进程列表绝对隔离：运行于 PRoot 容器内的进程（如 Python 解释器、Bash 终端）在尝试执行 ps 或读取 /proc 时，仅能观测到由 PRoot 派生的容器内部子进程，物理上绝对无法探知 Android 操作系统前台运行的微信、网银、游戏等第三方宿主进程的存在，确保了不同应用间运行状态的绝对隔离。
14.3 【无特权执行与用户身份映射（UID 0 虚拟化）】
在 PRoot 容器内部，终端提示符通常显示为 root（UID 0），这是为了满足 Ubuntu 软件包管理系统（如 apt、dpkg）在安装编译依赖时对特权身份的格式要求。维护团队在此向用户进行极其重要的计算机安全原理解析：
  ▶ （1）虚拟 Root 的本质是非特权执行：PRoot 内部显示的 root 身份纯属基于 ptrace 的“假特权”（Fake Root）。该虚拟 root 身份的所有行为映射回 Android Linux 内核时，其实际有效用户身份（EUID）始终且唯一地严格受限于宿主分配的普通非特权应用身份（如 u0_a1234）；
  ▶ （2）绝对无法危害系统底层：该虚拟 root 身份在物理上无法修改 Android 系统分区的任何文件、无法关闭 SELinux 强制防护、无法读取系统加密证书存储区。因此，容器环境的运行绝对不会为恶意程序在设备上实施系统级越权提供攻击跳板。
14.4 【容器内临时文件与套接字的生命周期安全】
在自动化任务执行期间，容器内的 Python 进程会通过标准 Unix Domain Socket（UDS）与本地回环套接字进行高速进程间通信，并在容器的 /tmp 目录生成临时套接字句柄文件。本软件部署了严格的退出清理守护钩子：在每次停止任务或宿主应用退出时，守护程序会自动执行 unlink 指令擦除 /tmp 目录下的所有临时文件与 IPC 管道，防止残留的套接字文件被设备上的其他恶意进程嗅探或复用。
14.5 【第三方 Linux 开源软件包的供应链隐私审查】
本软件所附带的 Rootfs 镜像文件，其基础组件均直接提取自 Ubuntu 官方 LTS 长期支持版发布的标准基础根文件系统包（Ubuntu Base Rootfs），并在 CI 构建流水线中通过自动化 Docker 容器进行标准化编排。维护团队严格把控软件供应链安全：在制作镜像的全流程中，绝不引入任何来源不明的未签名第三方 PPA 软件源，绝不编译任何闭源黑盒二进制组件，确保整个 Linux 运行环境的每一行代码均具备可溯源的开源合规性。
14.6 【容器网络协议栈的数据流转隔离】
PRoot 容器不具备独立的网络虚拟化命名空间（Network Namespace），其网络调用完全借由宿主 Android 系统的 Linux 网络堆栈下发。这意味着：
  ▶ （1）网络权限完全继承自宿主：容器内部的任何网络请求，均严格受限于 Android 系统向本宿主应用授予的 INTERNET 权限状态。若用户在系统设置中切断了本软件的“移动网络与 Wi-Fi 访问权限”，容器内部的 Python 脚本将瞬间失去一切联网能力；
  ▶ （2）无私自网络外联能力：容器环境绝对无法绕过系统的防火墙配置向任何未授权节点建立隐秘通信信道。
14.7 【多用户与分身环境下的沙箱一致性】
在部分支持“手机分身”、“应用双开”、“工作资料夹（Work Profile）”的定制 Android 系统中，操作系统会为不同的分身环境分配不同的 Linux 用户标识符（如 UserId 10、UserId 999）。本软件能够完美适应多用户隔离架构：在分身环境中运行的本软件，其 PRoot 容器文件系统完全创建在该分身专属的独立存储沙箱中，与主用户环境下的数据在文件系统底层完全物理隔离，两者的配置与日志互不相通，彻底杜绝多账号环境下的数据串联与交叉污染。
14.8 【运行时完整性自检与防篡改机制】
为了防止恶意软件在本地篡改 PRoot 容器内的关键 Python 自动化脚本或植入钓鱼页面，本软件在每次启动前均会执行关键文件的 SHA-256 哈希完整性自检。一旦检测到核心自动化逻辑脚本被外部非法篡改，本软件将拒绝启动并弹出安全警告，提示用户执行重装修复，以此捍卫用户本地数据处理逻辑的真实性与纯洁性。

15. 图像识别模板匹配与深度学习神经网络模型本地推理数据流全链路审查
15.1 【计算机视觉数据流在本地内存中的流转拓扑】
本软件的核心视觉感知系统依赖于高度优化的本地计算机视觉管线。为了消除关于“图像是否会被云端后台偷看”的疑虑，维护团队将截屏图像数据从产生到销毁的全生命周期内存流转路径进行全景式公开审查：
  ▶ （1）像素采集源头：通过 Android MediaProjection 接口建立虚拟 Surface，硬件图形合成器将物理屏幕的渲染像素拷贝至系统分配的 GraphicBuffer 物理内存页；
  ▶ （2）零拷贝 Native 映射：Native 桥接层动态库通过 libandroid.so 的 AImageReader_acquireLatestImage API 获取最新的图像帧句柄，并通过直接内存映射指针（Direct Pointer）将 RGBA_8888 像素矩阵直接接入 C++ 运算空间，全流程不产生额外的中间副本；
  ▶ （3）色彩空间转换与矩阵切片：OpenCV 算法库调用 cv::cvtColor 将 RGBA 矩阵转换为用于模板匹配的灰度图（GRAY）或三通道 BGR 矩阵，并根据当前任务所关注的屏幕特定 ROI 感兴趣区域（Region of Interest）执行矩形裁剪切片；
  ▶ （4）算法比对与立即释放：特征匹配算法在内存中完成互相关系数矩阵计算后，OpenCV 的 cv::Mat 智能指针引用计数归零，底层的图像像素内存区域立即被析构释放并标记为可重用，其存活周期通常仅维持数毫秒至十余毫秒；
  ▶ （5）绝无外发管道：在上述全链路中，代码中绝对不包含任何将图像缓冲区通过 Socket、HTTP、FTP 等网络协议发往外网的逻辑，图像像素矩阵的生与死完全被锁死在单机 RAM 硬件芯片之中。
15.2 【LiteRT 神经网络轻量级模型推理隐私安全】
本软件集成了由 Google 官方主导研发的 LiteRT（原 TensorFlow Lite）端侧轻量级机器学习推理框架，用于执行光学字符识别（OCR）。维护团队就该深度学习模型的运行特性说明如下：
  ▶ （1）模型文件本地离线存储：用于文字检测与识别的神经网络权重模型文件（.tflite 格式）以只读资产形式随本软件安装包一并离线打包分发（存放于 assets/ 目录中）。本软件在执行文字推理时，完全通过本地 CPU 或 GPU 硬件加速器加载该模型文件，绝对无需向任何外部云端 AI 接口（如各大云厂商的公有云 OCR API）上传任何图像切片；
  ▶ （2）输入输出特征张量的即时内存覆写：神经网络在执行推导时，输入的图像张量（Tensor）以及输出的字符概率分布矩阵，在推理函数完成前向传播（Forward Pass）并解码为最终的 UTF-8 文本后，张量内存缓冲区立即被框架的分配器释放，不保留任何可逆推原始画面的历史隐空间特征向量；
  ▶ （3）模型无持续学习与反向传播：本软件内置的 LiteRT 模型属于预先训练固化的离线推理模型，在用户端设备上仅执行前向推导，绝对不执行任何本地反向传播（Backpropagation）训练，因此不存在将用户的个人游戏画面反向固化融入神经网络权重并泄露的技术可能。
15.3 【屏幕水印、反截图与敏感应用窗口规避】
在移动设备日常使用中，用户难免需要打开涉及财产隐私的应用程序（如手机银行、密码保险箱、个人所得税等）。维护团队明确告知本软件对系统敏感窗口的尊重机制：
  ▶ （1）FLAG_SECURE 硬件安全窗口规避：当用户在前台打开声明了 WindowManager.LayoutParams.FLAG_SECURE 标志的高安全等级应用（如网银密码输入界面、加密通讯软件私聊界面）时，Android 操作系统底层的 SurfaceFlinger 合成器会在硬件级别对该窗口实施保护，本软件通过 MediaProjection 捕获到的该区域画面将直接被系统强制替换为纯黑像素（Black Out），本软件在底层物理上完全无法截取到受保护窗口的任何真实像素；
  ▶ （2）独立虚拟屏幕的天然物理隔离：当用户采用特权模式在第二虚拟屏幕上运行游戏时，虚拟屏幕的渲染图层堆栈与主物理屏幕完全属于不同的窗口上下文。用户在主屏幕上的微信聊天、照片浏览、网页浏览等一切私人操作，在操作系统图层层面与虚拟屏幕完全不发生任何重叠，虚拟屏的图像采集管线完全不可见用户主屏幕的任何隐私画面，构筑起最为坚固的物理显示隔离防线。
15.4 【异常死锁截图排障落盘的透明可审计性】
如前文所述，在发生界面死锁或连续匹配超时等极端技术故障时，系统可能将故障发生瞬间的一帧画面保存至本地 debug/ 临时目录。为了保障该机制的绝对透明，维护团队做出了如下合规保障设计：
  ▶ （1）保存行为完全受用户控制：用户可在软件设置中的“高级与调试”面板中，自主找到“允许保存错误截图”的开关，用户可随时将其完全关闭。关闭后，系统即便遭遇连续死锁报错，亦绝对不在物理磁盘中保存任何一帧图片；
  ▶ （2）截图保存路径完全公开：所有排障截图均以公开透明的标准 PNG 格式存储于设备的应用内部私有路径中，用户随时可通过内置的日志管理面板逐张预览、全选并立即一键彻底物理删除；
  ▶ （3）绝不自动静默上传：保存的截图仅供用户个人在本地肉眼核查排障，或在用户深度脱敏后自主提交至社区求助。本软件绝对不在后台默默打包该等截图向任何外部地址进行定时回传。
15.5 【用户自定义模板库与图像特征的安全存放】
部分高阶用户利用上游 AzurPilot 框架的高级自定义功能，通过 WebUI 自行裁剪并上传了个性化的游戏界面模板特征图（Custom Assets）。用户知悉：所有由用户自主上传或导入的图片资源，均保存在本地 PRoot 容器的对应 assets 目录中。本软件严格将其作为用户的私有资产进行本地存储保护，绝不在未经用户授权的情况下将用户的私人模板向公共仓库进行回传。
15.6 【屏幕像素灰度化与特征哈希降维处理】
为了进一步压缩内存占用并提升处理安全性，图像引擎在许多场景下会对原始彩色像素进行灰度化（Grayscale）与高斯模糊降维处理，仅提取边缘轮廓（Canny Edge）与特征哈希（pHash）。这种信息单向不可逆的降维数学变换，在客观上使得临时处理中的特征数据进一步脱敏，最大程度降低了像素流中附带的人类可读个人隐私信息密度。
15.7 【第三方反作弊扫描与屏幕捕获对抗免责】
用户知悉：第三方游戏客户端自身所集成的安全防护 SDK 可能会在游戏运行时，通过调用系统 API 检索系统中是否存在处于活跃状态的虚拟显示屏或媒体投屏服务。本软件对屏幕画面的捕获行为在操作系统层面属于合法公开的 API 交互，若第三方游戏运营商依据其自身的安全审计规则将投屏采集行为判定为风险事件，该法律风险完全属于用户使用第三方游戏所伴生的既有风险，维护团队对游戏运营商的检测行为免责。
15.8 【算法纯洁性终局审计声明】
维护团队在此向所有安全审计机构、代码审计员及广大用户作出郑重声明：本软件的全部图像处理算法与模型调用逻辑，均接受全社会的公开开源监督。代码中不存在任何针对人脸识别数据、身份证文字、信用卡卡号进行定向爬取与隐秘窃取的恶意规则，全套视觉识别体系的唯一技术指向，即为手机游戏界面的标准 UI 控件与关卡文字。

16. 嵌入式 WebUI、WebSocket 网关与本地 IPC 通信安全防护体系
16.1 【本地 Web 控制台网络拓扑与安全防护定位】
本软件集成了基于现代化前端框架构建的本地 WebUI 交互控制台，以及基于 Python aiohttp / FastAPI 架构构建的后端 RESTful 与 WebSocket API 网关。该 Web 架构旨在向用户在移动设备屏幕上提供现代化触控配置交互界面。维护团队就系统内部通信安全与数据隐私披露如下：
  ▶ （1）默认回环网络闭环绑定（127.0.0.1）：在默认安全配置下，本软件内置的 Web 守护进程被严格配置为仅监听在本地回环网络接口（Loopback Interface, 127.0.0.1:25548）。该网络接口是操作系统内核内部的一套纯软件虚拟网络层，其产生的一切 TCP 报文与 WebSocket 数据帧仅在设备物理内存中被直接短路转发，完全不经过设备外部的物理网卡芯片（Wi-Fi 或蜂窝天线）。这意味着，在外部局域网或公网上的任何其他设备，在物理上均无法探测到该端口的存在，亦绝对无法向该回环端口发送任何网络报文；
  ▶ （2）双重身份认证防火墙（Token-Based Authentication）：为了防止设备上安装的其他恶意第三方应用利用同一局域网回环权限擅自调用控制接口，本软件设计了极其严密的身份鉴权体系。所有向 WebUI 网关发起的 HTTP 资源请求与 WebSocket 握手建立请求，均必须在请求头中携带高熵值的有效安全令牌（X-Api-Token / Authorization Bearer Token）或通过加密 Session Cookie 校验。任何未携带有效 Token 的非法请求，将被网关在握手阶段瞬间以 HTTP 401 Unauthorized 状态码强制拒绝连接。
16.2 【跨站请求伪造（CSRF）与跨域资源共享（CORS）严密防御】
在移动互联网环境下，恶意网页可能试图诱导用户在浏览器中打开特定钓鱼页面，并利用该页面的 JavaScript 脚本向本地回环地址（http://127.0.0.1:...）发送非法的跨域异步请求，试图窃取本地配置或控制软件。为了彻底封死此类高危网络漏洞，本软件在 Web 后端网关部署了银行级别的跨域防御策略：
  ▶ （1）严格的 Origin 与 Referer 来源校验：网关会严密审查每一个传入请求的 Origin 请求头，仅允许来自本软件内部 WebView 组件（如特定 Android 内部协议头）或用户明确配置的受信域名的访问请求；
  ▶ （2）禁止凭据跨域共享：网关强制关闭了针对非受信域名的 Access-Control-Allow-Origin 通配符支持，严格禁止浏览器在跨域场景下传递敏感身份凭据；
  ▶ （3）WebSocket 握手来源阻断：在建立实时日志流与状态推送的双向 WebSocket 连接时，网关会严格比对握手报文的来源地址，彻底拦截来自外部恶意网站发起的非法 WebSocket 劫持连接（CSWSH 攻击）。
16.3 【本地进程间通信（IPC）机制与数据安全通道】
本软件由 Android 原生宿主应用进程（Kotlin）与 PRoot 容器内部的 Python 自动化进程两个独立运行实体协同组成。两层体系之间的本地通信采用了高度隔离且可信的 IPC 数据通道：
  ▶ （1）标准输入输出管道守护（Stdin/Stdout Pipe）：宿主进程通过底层标准 POSIX 管道向子进程发送保活脉冲与生命周期终止信号，管道受 Linux 进程树权限严格保护，外部未授权进程无法截获管道内容；
  ▶ （2）本地回环私有协议加密流转：宿主应用的前端控制指令与子进程的执行状态上报，均通过内部自定义的 JSON-RPC 协议在 127.0.0.1 回环网络中受限传输。传输的数据结构严格限定于任务状态枚举（如 TaskState.RUNNING）、当前执行轮次计数、报错文本描述，绝不包含任何系统级敏感数据或用户真实身份隐私。
16.4 【WebUI 前端本地静态资源安全性审查】
嵌入于本软件内部的 Web 网页前端静态资源（涵盖 HTML 骨架、CSS 样式表、编译后的 JavaScript 打包产物、字体库及 SVG 图标），全部随软件安装包以离线静态资产形式内置在本地存储中。在用户使用本软件自带的 WebView 界面进行操作时：
  ▶ （1）纯离线加载与零外部 CDN 脚本依赖：所有的 JS 库（如 Vue / React / Tailwind 等前端框架代码）均直接从设备本地磁盘加载解析，绝对不动态从外部商业 CDN 加速节点远程加载任何可能被中间人篡改或带有追踪代码的第三方外部脚本；
  ▶ （2）内容安全策略（Content Security Policy, CSP）防护：Web 页面部署了严苛的 CSP 响应头规则，禁止页面动态执行任何未经哈希验证的内联脚本（unsafe-inline），禁止从外部不可信域名加载图片或发起异步请求，全面抵御跨站脚本攻击（XSS）。
16.5 【局域网开放控制模式下的传输加密与防暴力破解】
当用户根据自身管理需要，在软件设置中主动开启“局域网控制（LAN Control）”并将监听绑定至 0.0.0.0 时，本软件自动提升安全防御等级：
  ▶ （1）IP 访问频率限制（Rate Limiting）：网关内置了基于内存漏桶算法的请求限流器，对来自同一局域网 IP 地址的未授权试探请求实施严密的频率限制。一旦检测到特定 IP 在 1 分钟内连续出现 5 次以上的 Token 密码认证失败，系统将自动将该局域网 IP 关入黑名单封锁 15 至 60 分钟，从根本上粉碎黑客利用密码字典实施的暴力破解攻击；
  ▶ （2）密码强哈希存储：用户设定的 Web 控制密码绝不以明文形式落盘保存，而是经过密码学安全单向哈希函数（如加盐 bcrypt 或 Argon2 算法）计算后存储其哈希摘要值。即使本地配置文件遭遇极端物理泄露，外部攻击者亦无法在有限时间内反向逆推明文密码。
16.6 【远程穿透会话（Remote Session）的状态隔离与断线销毁】
在远程访问高级模式下，为了防范会话被重放或长久滞留，本软件建立了严格的会话生命周期时效机制：
  ▶ （1）短期有效期与动态刷新：远程访问发放的临时管理凭证被设置了合理的生命周期限制，超时未活动将自动强制注销会话；
  ▶ （2）一键终止远程活跃连接：用户在手机本地界面中随时可点击“终止所有当前网络会话”，网关将瞬间强制切断并关闭所有当前处于连接状态的外部远程 TCP 与 WebSocket 通道，立即令所有的外部远程控制端强制下线。
16.7 【网络状态监听的隐私极小化】
本软件申请并在后台监听设备网络状态变化（ACCESS_NETWORK_STATE），其唯一用途在于感知当前网络是否由家庭受信任 Wi-Fi 切换为了移动蜂窝网络，以便在网络变动时向用户弹出提示，防止在未知网络环境下继续暴露局域网端口或意外消耗手机高额蜂窝流量。本软件绝不利用网络监听接口搜集周围环境中的 Wi-Fi 路由器 BSSID、SSID 广播名称或基站小区识别码，绝不利用网络环境搜集用户的粗略或精确物理地理位置。
16.8 【Web 架构纯粹性与开源代码可审计性承诺】
维护团队再次向用户庄重宣告：本软件内置的整个 Web 服务与通信中间件体系，完全基于公开、成熟、经过全球数百万开发者广泛审计的标准开源组件构建。系统内部绝不包含任何用于商业数据收集的私有跟踪协议，绝不向任何商业云平台回传控制日志。用户完全拥有在本地彻底关闭 Web 服务的绝对自由。

17. 自动化状态机、业务调度流水线与游戏资产相关参数的本地脱敏治理
17.1 【有限状态机（FSM）调度引擎之数据流转脱敏原理】
本软件驱动游戏执行全流程的核心，是一套极其庞大、严密的有限状态机（Finite State Machine, FSM）业务调度引擎。状态机引擎在不断循环的“捕获图像 -> 匹配当前界面状态 -> 决策下一步操作 -> 派发触控事件 -> 等待响应”的闭环状态链条中运作。维护团队深入贯彻数据治理中的“隐私设计（Privacy by Design）”工程哲学，确保状态机在全流程中的所有业务参数流转均实施严格的本地脱敏隔离。
17.2 【出击与战斗调度模块的资产脱敏规范】
在执行主线关卡、困难战役、限时活动出击任务期间：
  ▶ （1）游戏关卡参数本地解析：关卡代号（如 7-2、12-4、13-4、SP4 等）仅作为纯文本字符串在内存调度队列中匹配预设的坐标寻路网格，绝不与任何外部用户身份信息进行绑定；
  ▶ （2）舰队编制数据无痕流转：出战舰船的角色编号、舰船等级仅用于判定是否满足出战门槛与心情阈值，相关状态数据完全停留在 RAM 内存变量中，在战斗结束结算并返回港区后立即被垃圾回收机制（GC）清理，不构建长久保存的舰队资产编成履历数据库；
  ▶ （3）掉落物品结算本地化：战斗胜利后界面掉落的新舰船、装备图纸、物资奖励由 OCR 模块进行瞬时识别并计数，其计数结果仅用于在 WebUI 面板上展示临时的“本次运行收益统计”。该统计数据属于易失性数据，软件关闭后即刻归零，绝不向任何外部服务器上报用户的欧气抽卡概率或掉落明细。
17.3 【演习与竞技场模块的战力数据瞬时销毁】

21.1 【数据全生命周期安全审计闭环】
依据国家关于数据安全治理的行业标准规范，本软件将个人信息在移动设备本地的处理流程细分为“产生 - 采集 - 传输 - 存储 - 使用 - 销毁”六大完整阶段，并在每一个独立阶段构建起坚实的密码学与工程学技术防御壁垒：

  ▶ （2）传输阶段：所有进程间通信（IPC）与容器内部数据流转仅限于本地系统内部虚拟总线，网络远程访问全程采用 TLS 1.3 / SSH-2 行业高强度加密隧道；
  ▶ （3）存储阶段：数据 100% 封闭在 Linux 私有沙箱内部，敏感密钥排除系统云备份；
  ▶ （4）使用阶段：内存数据即时计算，绝不构建任何违背用户初衷的商业画像与统计模型；
  ▶ （5）销毁阶段：日志轮换自动清理、临时图像随退即焚、应用卸载物理扇区全面抹除。
21.2 【去标识化哈希算法在数据诊断中的实践】
为了在向开源社区报告复杂技术故障时最大程度保护用户的数字人格与隐私权，本软件在生成内部诊断快照时，引入了基于 SHA-256 密码学哈希函数的单向去标识化机制。系统自动将部分偶发出现的设备内部标识符转化为不可逆的固定长度哈希摘要（如 hash("device_id_salt") -> a1b2c3d4...）。该摘要仅作为区分不同测试设备的临时符号，外部任何机构均无法依据该哈希摘要反向逆推用户的真实硬件参数或个人身份。
21.3 【跨进程共享内存（Shared Memory）的访问权限收紧】
在 Native 桥接层与 Java/Kotlin 宿主层之间传递大容量屏幕帧图像时，本软件采用 Android 底层标准 ashmem（Android Shared Memory）或 Linux memfd 匿名文件句柄。维护团队在代码底层对该共享内存句柄设置了极其严厉的保护标志：
  ▶ （1）仅允许宿主应用进程与其合法派生的特权 app_process 子进程通过 Binder IPC 传递该文件描述符（File Descriptor, FD）；
  ▶ （2）内存区域被设置为只读（PROT_READ）共享，防止子进程意外篡改原始图形数据；
  ▶ （3）外部任何未持有合法 Binder 令牌的第三方恶意进程，在操作系统内核级别均被禁止映射该共享内存段，有力捍卫了像素流的内存级机密性。
21.4 【针对侧信道攻击（Side-Channel Attack）的防御机制】
在极端高对抗的安全威胁模型下，黑客软件可能尝试通过监视设备的 CPU 瞬时功耗曲线、缓存命中率（Cache Miss Rate）或特定系统广播的时序差，推断当前游戏屏幕是否发生了特定变化（即所谓的微架构侧信道攻击）。本软件的状态机引擎在调度算法中引入了时间维度的平滑缓冲与虚假操作填充（Dummy Operation），使得整体计算任务的 CPU 负载呈现平缓的均匀分布，极大增加了外部侧信道分析的信噪比与破解难度。
